# CATALOG-01. Пустой каталог

## Назначение

Подтвердить понятное состояние каталога без категорий.

## Предусловия

Administrator авторизован. В каталоге нет категорий.

## Сценарий

1. Administrator открывает раздел «Меню».

## Ожидаемый результат

- Administrator видит сообщение «Категорий пока нет. Добавьте первую категорию».
- Administrator видит действия добавления категории и товара.

# CATALOG-02. Создание валидной категории

## Назначение

Подтвердить создание активной категории с корректными данными.

## Предусловия

Administrator авторизован. Категории с выбранным названием нет.

## Сценарий

1. Administrator нажимает «Добавить группу».
2. Administrator указывает название категории.
3. Administrator указывает описание категории.
4. Administrator сохраняет категорию.
5. Administrator открывает редактирование созданной категории.

## Ожидаемый результат

- Administrator видит созданную категорию с указанными названием и описанием.
- Administrator видит включённый переключатель «Категория активна».

# CATALOG-03. Валидация категории

## Назначение

Подтвердить, что категория не сохраняется без обязательного названия.

## Предусловия

Administrator авторизован.

## Сценарий

1. Administrator нажимает «Добавить группу».
2. Administrator очищает название категории.

## Ожидаемый результат

- Administrator видит сообщение «Введите название категории».
- Действие сохранения категории недоступно.

# CATALOG-04. Редактирование категории

## Назначение

Подтвердить изменение данных существующей категории.

## Предусловия

Изолированный профиль `catalog-mutation` предоставляет роль Administrator и
категорию «Кофе».

## Сценарий

1. Administrator открывает управление меню.
2. Administrator открывает редактирование категории «Кофе».
3. Administrator изменяет название категории на «Кофе — обновлено».
4. Administrator изменяет описание категории на «Обновлённое описание категории
   кофе.».
5. Administrator сохраняет изменения.
6. Administrator открывает редактирование категории «Кофе — обновлено».

## Ожидаемый результат

- Administrator видит категорию «Кофе — обновлено» с описанием «Обновлённое
  описание категории кофе.».

# CATALOG-05. Порядок категорий

## Назначение

Подтвердить изменение порядка категорий в каталоге.

## Предусловия

Изолированный профиль `catalog-mutation` предоставляет роль Administrator и
категории «Кофе» и «Выпечка» в этом порядке.

## Сценарий

1. Administrator открывает раздел «Меню».
2. Administrator открывает управление меню.
3. Administrator перемещает категорию «Выпечка» вверх.

## Ожидаемый результат

- Administrator видит категорию «Выпечка» перед категорией «Кофе».
- Для категории «Выпечка» действие перемещения вверх недоступно.

# CATALOG-06. Архивирование категории

## Назначение

Подтвердить отмену и подтверждение архивирования категории.

## Предусловия

Изолированный профиль `catalog-mutation` предоставляет роль Administrator и
активную категорию «Выпечка».

## Сценарий

1. Administrator открывает управление меню.
2. Administrator открывает редактирование категории «Выпечка».
3. Administrator запрашивает архивирование категории «Выпечка».
4. Administrator отменяет архивирование категории «Выпечка».
5. Administrator повторно запрашивает архивирование категории «Выпечка».
6. Administrator подтверждает архивирование категории «Выпечка».

## Ожидаемый результат

- После отмены категория остаётся в каталоге.
- После подтверждения категория отсутствует среди активных категорий.

# CATALOG-07. Напиток с размерами

## Назначение

Подтвердить создание напитка с доступными размерами и ценами.

## Предусловия

Administrator авторизован. В каталоге есть категория.

## Сценарий

1. Administrator нажимает «Добавить товар».
2. Administrator выбирает категорию товара.
3. Administrator выбирает тип «Напиток».
4. Administrator указывает название товара.
5. Administrator указывает цену размера S.
6. Administrator указывает цену размера M.
7. Administrator указывает цену размера L.
8. Administrator сохраняет товар.

## Ожидаемый результат

- Administrator видит созданный напиток в выбранной категории.
- В карточке товара показаны размеры S, M и L с указанными ценами.

# CATALOG-13. Группа и варианты добавок

## Назначение

Подтвердить создание обязательной группы добавок с вариантом по умолчанию.

## Предусловия

Administrator авторизован.

## Сценарий

1. Administrator открывает управление меню.
2. Administrator нажимает «Новая группа опций».
3. Administrator указывает название группы.
4. Administrator включает обязательность группы.
5. Administrator выбирает одиночный тип выбора.
6. Administrator добавляет вариант.
7. Administrator указывает название варианта.
8. Administrator указывает нулевое изменение цены.
9. Administrator включает выбор варианта по умолчанию.
10. Administrator сохраняет группу.

## Ожидаемый результат

- Administrator видит созданную группу добавок.
- Administrator видит созданный бесплатный вариант, выбранный по умолчанию.

# CATALOG-14. Порядок добавок

## Назначение

Подтвердить изменение порядка вариантов добавок в группе.

## Предусловия

Изолированный профиль `catalog-mutation` предоставляет роль Administrator и
группу «Молоко» с вариантами «Обычное молоко» и «Овсяное молоко» в этом порядке.

## Сценарий

1. Administrator открывает управление меню.
2. Administrator открывает редактирование группы «Молоко».
3. Administrator перемещает вариант «Овсяное молоко» вверх.
4. Administrator сохраняет группу.
5. Administrator открывает редактирование группы «Молоко».

## Ожидаемый результат

- Administrator видит вариант «Овсяное молоко» перед вариантом «Обычное молоко»
  в группе добавок.
- Для варианта «Овсяное молоко» действие перемещения вверх недоступно.

# CATALOG-15. Назначение группы добавок категории

## Назначение

Подтвердить назначение существующей группы добавок категории и валидацию порядка.

## Предусловия

Изолированный профиль `catalog-mutation` предоставляет роль Administrator,
категорию «Выпечка» и не назначенную ей группу «Молоко».

## Сценарий

1. Administrator открывает управление меню.
2. Administrator открывает назначения категории «Выпечка».
3. Administrator назначает группу «Молоко».
4. Administrator указывает порядок группы «-1».
5. Administrator указывает порядок группы «0».
6. Administrator сохраняет назначения.

## Ожидаемый результат

- Administrator видит сообщение «Укажите неотрицательный порядок для каждой
  группы».
- После исправления Administrator видит назначенную группе «Молоко» категорию
  «Выпечка» с порядком «0».
