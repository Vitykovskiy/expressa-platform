# CATALOG-01. Пустой каталог

## Назначение

Подтвердить понятное состояние каталога без категорий.

## Предусловия

Administrator авторизован. В каталоге нет категорий.

## Сценарий

1. Administrator открывает раздел «Меню».

## Ожидаемый результат

- Administrator видит сообщение «Категорий пока нет. Добавьте первую категорию».
- Administrator видит действия добавления категории и товара.

# CATALOG-02. Создание валидной категории

## Назначение

Подтвердить создание активной категории с корректными данными.

## Предусловия

Administrator авторизован. Категории с выбранным названием нет.

## Сценарий

1. Administrator нажимает «Добавить группу».
2. Administrator указывает название категории.
3. Administrator указывает описание категории.
4. Administrator сохраняет категорию.
5. Administrator открывает редактирование созданной категории.

## Ожидаемый результат

- Administrator видит созданную категорию с указанными названием и описанием.
- Administrator видит включённый переключатель «Категория активна».

# CATALOG-03. Валидация категории

## Назначение

## Ожидаемый результат

# CATALOG-06. Архивирование категории

## Назначение

Подтвердить отмену и подтверждение архивирования категории.

## Предусловия

Administrator и customer авторизованы. В каталоге есть категория. Customer имеет
завершённый заказ с товаром этой категории.

## Сценарий

1. Administrator открывает управление меню.
2. Administrator открывает редактирование категории.
3. Administrator нажимает «Архивировать категорию».
4. Administrator отменяет архивирование.
5. Administrator нажимает «Архивировать категорию».
6. Administrator подтверждает архивирование.
7. Customer открывает раздел «История».
8. Customer открывает завершённый заказ.

## Ожидаемый результат

- После отмены категория остаётся в каталоге.
- После подтверждения категория отсутствует среди активных категорий.
- Customer видит неизменный снимок товара, размера, добавок, количества и суммы
  завершённого заказа.

# CATALOG-07. Напиток с размерами

## Назначение

Подтвердить создание напитка с доступными размерами и ценами.

## Предусловия

Administrator авторизован. В каталоге есть категория.

## Сценарий

1. Administrator нажимает «Добавить товар».
2. Administrator выбирает категорию товара.
3. Administrator выбирает тип «Напиток».
4. Administrator указывает название товара.
5. Administrator указывает цену размера S.
6. Administrator указывает цену размера M.
7. Administrator указывает цену размера L.
8. Administrator сохраняет товар.

## Ожидаемый результат

- Administrator видит созданный напиток в выбранной категории.
- В карточке товара показаны размеры S, M и L с указанными ценами.

# CATALOG-13. Группа и варианты добавок

## Назначение

Подтвердить создание обязательной группы добавок с вариантом по умолчанию.

## Предусловия

Administrator авторизован.

## Сценарий

1. Administrator открывает управление меню.
2. Administrator нажимает «Новая группа опций».
3. Administrator указывает название группы.
4. Administrator включает обязательность группы.
5. Administrator выбирает одиночный тип выбора.
6. Administrator добавляет вариант.
7. Administrator указывает название варианта.
8. Administrator указывает нулевое изменение цены.
9. Administrator включает выбор варианта по умолчанию.
10. Administrator сохраняет группу.

## Ожидаемый результат

- Administrator видит созданную группу добавок.
- Administrator видит созданный бесплатный вариант, выбранный по умолчанию.

# CATALOG-15. Назначение группы добавок категории

## Назначение

Подтвердить назначение существующей группы добавок категории и валидацию порядка.

## Предусловия

Administrator авторизован. В каталоге есть категория и не назначенная ей группа
добавок.

## Сценарий

1. Administrator открывает управление меню.
2. Administrator выбирает категорию для настройки добавок.
3. Administrator назначает существующую группу добавок.
4. Administrator указывает отрицательный порядок группы.
5. Administrator указывает неотрицательный порядок группы.
6. Administrator сохраняет назначения.

## Ожидаемый результат

- Administrator видит сообщение о необходимости указать неотрицательный порядок.
- После исправления Administrator видит назначенную группе добавок категорию и её порядок.
