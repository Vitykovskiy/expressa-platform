# Журнал изменений

Записи ниже фиксируют начальные выпуски E01 и их поставку на стенды.

## front-office v0.1.2 (2026-08-31)

- В мобильной корзине доступно действие «Меню», возвращающее к меню до создания заказа.

## front-office v0.1.1 (2026-08-31)

- В корзине при изменении цены показываются предыдущий и новый итоги на мобильной и широкой раскладках.

## staging v0.2.10

Аннотированный тег `staging-v0.2.10` на SHA
`de01cc3f4ed29cd61525b3ed96defd476c2d74c1` поставил совместимый набор
immutable digest из успешного Development run `31928967912` для SHA
`fc365d8c8652bc3e2a8bbc3b8eb51ff3427bcbb8` (manifest SHA256
`0b58c33860aec1108d16e4ae3ca154d9142fe0d517e0eeca1e178d5241c3c6dc`).
Staging run `31929440771` применил миграции, идемпотентный seed, health
проверки трёх приложений, public menu и полный сценарий заказа. Версии
компонентов не меняются: backend `v0.2.0`, front-office `v0.1.0`,
back-office `v0.1.0`.

## staging v0.2.9 (выполненная повторная поставка доказательств)

Тег `staging-v0.2.9` повторно поставил в staging тот же совместимый
набор immutable digest для сбора проверяемых доказательств. Это составной тег
поставки, а не выпуск компонентов.

## staging v0.2.8

Тег `staging-v0.2.8` зафиксировал совместимый набор backend `v0.2.0`,
front-office `v0.1.0` и back-office `v0.1.0`. Это составной staging-тег;
версии пакетов компонентов уже находятся в неизменяемых образах и не меняются
при повторной поставке доказательств.

## staging v0.2.0

Совместимый набор backend `v0.2.0`, front-office `v0.1.0` и back-office
`v0.1.0` реорганизует границы приложений, переносит Storybook из runtime-кода
и вводит проверяемую документацию по каждому контуру.

## backend v0.2.0

- Добавлена локальная документация архитектуры, доменов, API, данных,
  эксплуатации и тестирования.
- Обновлены зависимости Swagger и `js-yaml` с устранением известных
  уязвимостей.

## front-office v0.1.0

- Runtime-код распределён по слоям `app`, `pages`, `widgets`, `features`,
  `entities` и `shared`.
- Storybook, его сценарии и проверки перенесены в `.storybook`.

## back-office v0.1.0

- Runtime-код распределён по слоям приложения и административным областям.
- Storybook и проверки изолированы в `.storybook`; уточнено адаптивное
  поведение навигации и экрана заказов.

## staging v0.1.1

Совместимый набор backend `v0.1.1`, front-office `v0.0.1` и back-office `v0.0.1` зафиксирован как фундаментальный staging-релиз E01.

## backend v0.1.1

- Зафиксирован релизный номер backend для базового E01-фундамента и поставки через CI/CD.

## front-office v0.0.1

- Зафиксирован релизный номер front-office для базового E01-фундамента и поставки через CI/CD.

## back-office v0.0.1

- Зафиксирован релизный номер back-office для базового E01-фундамента и поставки через CI/CD.

## backend v0.1.0

- Добавлен автономный NestJS backend с PostgreSQL, миграциями и валидацией окружения.
- Добавлен версионированный HTTP API `/api/v1`, OpenAPI для local и development, health-check и requestId.

## front-office v0.0.0

- Добавлено автономное Vue PWA-приложение с маршрутами меню, корзины, авторизации, текущего заказа и истории.
- Добавлены локальное состояние, API-клиент и отображение ошибок; API вызывается через same-origin `/api`.

## back-office v0.0.0

- Добавлено автономное Vue PWA-приложение для staff-контура с маршрутами, локальным состоянием, API-клиентом и обработкой ошибок.
- API вызывается через same-origin `/api`.

## staging v0.1.0

Совместимый набор backend `v0.1.0`, front-office `v0.0.0` и back-office `v0.0.0` развёрнут по immutable digest в staging тегом `staging-v0.1.0`.
