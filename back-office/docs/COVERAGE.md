# Покрытие runtime back-office

Реестр описывает текущие реальные потребители, а не независимую приёмку.
Все рабочие разделы подключены к оболочке. Vue Router выбирает пять named страниц;
модуль orders валидирует только бизнес-query. Локальные ручные наблюдения и
нетестовые проверки исполнителя не заменяют независимые review, native click,
повторный запуск полного установленного клиента и development-поставку.
Автоматизированные тесты не создавались, не изменялись и не запускались.

После переноса пути ниже соответствуют предметным `modules` и `layouts` по
[размещению кода](80-conventions/code-layout.md). Независимое source-review
предметных частей не принимает итоговую интеграцию или runtime: отметки
`independent review pending` относятся к этой остающейся проверке продукта.
Исторические native-наблюдения сохраняют ограничения своих исходных состояний.

Версии HTTP в реестре обозначают действующие серверные контракты.
Accept/issue используют v2 и проверяемый `OrderCoreDto`; чтение заказов и
ready/reject используют полный `OrderDto`. Сохранение метаданных отправленного
заказа после проверки покупателя остаётся текущей адаптацией ответа.
Подробности — в [HTTP-ноте](10-architecture/staff-read-slice.md#http-снимок).

## Реестр

Собранный Nginx передаёт application paths в SPA, где `/` и неизвестные пути
redirect на orders. Известные пути не затеняются public directories. Missing
static/API сохраняют свои HTTP-ответы; /sw.js остаётся missing static404.
Текущий worker /service-worker.js признаёт пять страниц и root; native
fallback направляет на /orders?order=UUID. Независимая G3 проверка ожидается.
