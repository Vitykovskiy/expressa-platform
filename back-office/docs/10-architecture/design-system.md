# Дизайн-система back-office 2.0

Основание проектируется с нуля для спокойного рабочего интерфейса: непрерывные
зоны, разделители, нейтральные поверхности и компактная иерархия действий.
Синий обозначает действие или выбор; красный — ошибку или опасное действие;
янтарный — предупреждение. Обычные статусы нейтральны. Дизайн ожидает приёмки.

## Источники и тема

Сырые цвета и semantic roles определены один раз в
[theme.constants.ts](../../src/shared/config/theme.constants.ts).
[tokens.css](../../src/shared/styles/tokens.css) выводит CSS aliases из Vuetify
theme variables и владеет типографикой, геометрией, focus, spacing и motion.
Системный шрифт поддерживает кириллицу. Основные controls имеют минимум 44px;
обычные поверхности не имеют теней. Тень используется только в overlay.

[theme.ts](../../src/app/theme.ts) — единственный владелец предпочтения.
При bootstrap читается сохранённое `light` или `dark` из
`expressa-back-office-theme`. При отсутствии, недоступности или неверном значении
используется системная тема; её изменения отслеживаются до явного выбора.
Выбор сохраняется по возможности. Ошибка storage не блокирует UI. Импорт
модуля не читает browser state; подписка очищается при unmount. CSS и Vuetify
обновляются одним владельцем. Storybook toolbar вызывает тот же контракт;
`system` возвращает следование системной теме.

Предпочтение `choice` (`system`, `light`, `dark`) и вычисленный режим `mode`
различаются у одного владельца. Toolbar показывает предпочтение; выбор текущего
режима всё равно фиксирует его явно. Смена системной темы меняет только режим,
пока предпочтение остаётся `system`.

## Публичные компоненты

Props, events и slots находятся рядом с каждым SFC в `*.types.ts`.

| Компонент     | Контракт и ответственность                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| UiButton      | primary / secondary / quiet / danger, disabled и loading блокируют activate; slot сохраняет доступное имя                  |
| UiTextField   | string model, явная метка, text/search/number без числового coercion; ошибка связана с полем                               |
| UiSelect      | string или null, readonly варианты value/label/disabled, controlled выбор и публичный VSelect                              |
| UiCheckbox    | controlled boolean, нативная семантика и связанная метка                                                                   |
| UiSwitch      | подтверждённый boolean и pending; сообщает intent, не меняет значение оптимистично                                         |
| UiFilterGroup | нативная группа radio с общим именем, клавиатурные стрелки и перенос на узкой ширине                                       |
| UiBadge       | нейтральный / предупреждение / ошибка, текст сообщает состояние без зависимости от цвета                                   |
| UiDialog      | controlled open, title, body/actions slots; фокус, возврат инициатору, policy закрытия и pending                           |
| UiFeedback    | loading / empty / error / success, короткий текст и опциональное действие; live announcement только динамических состояний |

Vuetify не создаёт бизнес-состояние. Wrapper Select задаёт размеры собственным
классом и наследуемыми sizing variables, без private DOM selectors.
Перенесённые меню и диалоги получают актуальные semantic aliases и тему.
Dialog использует публичный focus retention VDialog, фокусирует первое
доступное действие и возвращает фокус после закрытия. Если содержимое превышает
видимую высоту, начальный фокус получает сама прокручиваемая поверхность: заголовок,
текст и действия доступны обычной прокруткой целого диалога. Открытые варианты
Select переносят полную метку через публичные item/title slots.
Недоступный вариант сохраняет Vuetify item props и сообщает `aria-disabled`
на элементе `role="option"`; клавиатура пропускает его при выборе.

## Композиция и каталог

[Workbench](../../src/app/workbench/FoundationWorkbench.vue) показывает реальные
компоненты в общей композиции. Максимальная ширина 1200px; от 960px две зоны
3:2, ниже одна; gutter 24px, ниже 600px — 16px. Это не layout сотрудника.
Скрытые ручные controls состояния позволяют завершить pending действием,
выбрать ошибку и длинную строку. Нет таймеров, mock API или бизнес-запросов.
Ошибка сохранения сохраняет черновик; switch ждёт подтверждения владельца.

Истории рядом с компонентами вручную демонстрируют доступные состояния.
`Основа/Композиция` показывает общий ритм, `Основа/Tokens` — реальные
источники цветов, типографики и расстояний. Истории не являются тестами.
При изменении компонента обновляйте его истории и этот контракт. При смене
tokens меняйте владельца, не копии в компонентах.

## Приёмка

Проверяются обе темы, ширины 320/768/1024/1440px и границы 600/960px, длинные
русские строки, 200% zoom, reduced motion, focus и клавиатура. Требуются WCAG AA
4.5:1 для обычного текста, 3:1 для крупного и функциональных границ.
Нетестовые команды принадлежат [README](../../README.md). После собственных
проверок обязателен независимый review живого UI. Следующий staff-этап начинается
после явного одобрения пользователя.
