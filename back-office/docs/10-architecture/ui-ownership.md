# Владение UI back-office

## Глобальные UI-заповеди — нормативная цель

Статус: обязательная целевая норма для всего UI front-office и back-office; она не описывает текущую реализацию и не является её приёмкой.

> 1. Все server/API/transport failures во всём приложении показываются исключительно через единую canonical notification system контура. Dialogs, pages, forms, panels, cards и другие локальные поверхности не рендерят server errors.
> 2. Один application-root notification service и один host обслуживают все операции контура. Локальные snackbar/toast/error-banner реализации запрещены. Технические сведения доступны только в console, без секретов и пользовательских данных.
> 3. Validation корректируемого значения показывается только у соответствующего поля. Domain refusals, limits и неподтверждённые операции классифицируются централизованно и показываются через notifications. Произвольный server message не становится field error.
> 4. Для каждого повторяющегося atom/pattern/composite/shell/action group/field/dialog/notification/navigation/state surface существует ровно один canonical shared component в обоснованном контуре. Consumers только параметризуют его.
> 5. Отдельные компоненты допустимы только для доказанно разных semantics. Цвет, размер, отступ, сущность, название экрана и визуальное предпочтение не являются основанием для дублирования.
> 6. В контуре ровно один canonical dialog shell. Он владеет header/body/footer/actions/close/loading/scroll и всеми layout/styles. Consumer header/footer/action layouts, nested cards и альтернативные dialog shells запрещены.
> 7. Header любого dialog: title слева, close справа. Footer содержит горизонтальные группы: optional destructive secondary слева; «Отмена», затем primary справа. Если группы не помещаются в доступную ширину, они переходят на отдельные строки без сжатия подписей. Destructive confirmation имеет один destructive primary. Порядок и styles одинаковы во всех dialogs и viewport states.
> 8. Все typography/spacing/colors/sizes/borders/radii/shadows/motion разрешаются через единую semantic token authority. Локальные literals и CSS-переопределения внутреннего вида shared components запрещены.
> 9. UI содержит только необходимые title/labels/data/current state/validation/actions и краткое существующее destructive consequence. Hints, tooltips, instructional placeholders, explanatory subtitles, support details и дублирующие тексты запрещены.
> 10. Shared fields владеют label/required/control/actual validation. Один label, одно актуальное field error; никаких hint rows и optional markers. Локальные native-control substitutes запрещены.
> 11. Storybook показывает реальные canonical components и реальные tokens с deterministic direct states. Story-only fixes, copied demos, скрытые API-зависимости и фиктивные успешные сценарии запрещены.
> 12. Миграция завершена только после перехода всех consumers обоих контуров, удаления дубликатов и независимой проверки source coverage и работающих сценариев. Четыре dialogs или один showcase не доказывают global completion.
> 13. Границу доступности back-office задаёт [ADR-010](../../../docs/20-architecture/ADR/ADR-010-back-office-interaction-boundary.md): специальные `aria-*`, `role`, `tabindex`, видимые focus rings, программный возврат фокуса и отдельное клавиатурное управление не добавляются. Нативный ввод в полях и работа кнопок мышью и касанием сохраняются.
> 14. Автоматизированные тесты до явной приёмки не создавать, не изменять и не запускать. После приёмки — только по отдельному прямому запросу. Новые вспомогательные validators/scripts/automation требуют отдельного прямого запроса.

### Binding global contract sections

G01–G08, G51–G58 and G65–G80 are binding rules for this durable authority. Exact normative source: `.codex/tmp/tasks/global-ui-rules-v1/astra-global-commandments.md`. This note does not claim runtime adoption before independent acceptance.

Для общего `AdminButton` целевая область нативной кнопки составляет не менее 48 × 48 px ниже 768 px и 44 × 44 px от 768 px, включая кнопки только с иконкой; текстовые кнопки сохраняют ту же минимальную высоту. Сенсорный указатель сохраняет минимум 48 px на широкой странице. Компактный вариант отличается внутренними отступами, а не уменьшением области нажатия. Локальные более крупные области сохраняются. Закрашивать всю область кнопки не требуется; соседние области не перекрываются. Это применение G54 к общему примитиву, требующее независимой проверки после изменения. Источники: [AdminButton.vue](../../src/shared/ui/admin/admin-button/AdminButton.vue), [main.css](../../src/styles/main.css), [G54](../../../.codex/tmp/tasks/global-ui-rules-v1/astra-global-commandments.md).

`App.vue` выбирает вход либо `AdminShell` по сессии; оболочка строит пункты из роли и передаёт навигацию и выход наружу. Загрузку каталога, авторизацию и предметные действия оболочка не выполняет. Local server-error presentation подлежит удалению при migration к canonical notification system. Источники: [App.vue](../../src/app/App.vue), [session.store.ts](../../src/app/session.store.ts), [navigation.ts](../../src/app/navigation.ts).

Единственный корневой `NotificationHost` всплывает по центру верхнего края viewport на любой ширине, вне потока основного экрана и выше канонической подложки диалога. Без уведомлений, при появлении и после закрытия геометрия заголовка, списка, формы, действий и навигации основного экрана не меняется. Исключение — содержимое канонического `AdminDialog`: оно размещается вне фактически занятой ограниченной области host с верхним отступом и промежутком, сохраняя читаемые заголовок, закрытие, действия и независимо прокручиваемое тело. Полноэкранная поверхность и подложка сохраняют весь viewport; при скрытом host восстанавливается адаптивная компоновка для текущего viewport без резервирования места под уведомление. При высоте до 400 px внутренние отступы диалога остаются компактными и без уведомления, чтобы сохранить целые нативные поля и кнопки над независимо прокручиваемым телом; прежние отступы короткого диалога не являются целью восстановления. При обычной высоте 812 px компоновка без уведомления сохраняется. Карточки имеют нейтральную поверхность, смысловой акцент и иконку; ширина ограничена, учитываются safe-area и боковые поля. Длинное содержимое прокручивается внутри ограниченного по высоте host, основной экран прокручивается отдельно, нижняя навигация остаётся видимой. Пустая область слоя не перехватывает нажатия. Это уточнённый целевой контракт размещения по замечанию пользователя, требующий независимой визуальной проверки после реализации, включая короткие и полноэкранные диалоги; он не подтверждает принятую реализацию, полноту уведомлений о серверных операциях и не меняет их жизненный цикл или источники. Источники: [App.vue](../../src/app/App.vue), [NotificationHost.vue](../../src/shared/ui/notifications/NotificationHost.vue), [AdminDialog.vue](../../src/shared/ui/admin/admin-dialog/AdminDialog.vue), [notification-layout.ts](../../src/shared/ui/notifications/notification-layout.ts), [AdminShell.vue](../../src/widgets/admin-shell/AdminShell.vue).

`MenuPage` владеет открытыми диалогами, раскрытием групп и выбранными сущностями; `catalog.store` начинается в `idle`, затем владеет данными и статусом `loading|ready|error`. После подтверждённого пустого ответа страница показывает действие «Добавьте первую категорию»; это отдельное implemented empty state, не ошибка. Контракт экрана — в [управлении каталогом](../30-domains/Catalog-management.md). Источники: [catalog.constants.ts](../../src/pages/admin/menu/catalog.constants.ts), [MenuPage.vue](../../src/pages/MenuPage.vue).

`MenuReorderPanel` владеет только локальным черновиком порядка, dirty-индикаторами и управлением порядком мышью и касанием; `MenuPage` владеет последовательной записью dirty scopes через `catalog.store`, компенсацией и обновлением подтверждённого каталога. Черновик не меняет API и не переживает только успешное закрытие режима. Источники: [MenuReorderPanel.vue](../../src/pages/admin/menu/MenuReorderPanel.vue), [useMenuReorderDraft.ts](../../src/pages/admin/menu/composables/useMenuReorderDraft.ts).

Порядок меню использует плотные строки одной высоты для категории и товара; расчёт виртуального списка соответствует фактической высоте строки. Название получает приоритет по ширине и до двух строк на узком экране; если текст обрезан, нажатие на него открывает полный текст в каноническом диалоге без увеличения высоты строки. Раскрытие, перемещение и drag различимы по пиктограммам; вторичные действия не заполняются акцентным цветом. Ручка drag показывается только там, где работает указатель мыши; кнопки перемещения сохраняют управление мышью и касанием. Их интерактивная область остаётся не менее 44 px при ширине от 768 px и 48 px ниже 768 px. Заголовок и действия сохранения/отмены остаются компактными на любой ширине; последний элемент списка доступен прокруткой. Во время записи порядка внешняя навигация и подтверждение сброса черновика заблокированы; после подтверждённого сохранения владелец страницы закрывает режим ровно один раз, при ошибке черновик остаётся для повтора или отмены. Запись показывает только статус «Сохраняем…» в панели, без общего статуса загрузки страницы. Ошибка записи и ошибка компенсации показываются через канонические уведомления с разными идентификаторами операций; успешная сверка каталога не скрывает ошибку записи, а успешный повтор может её закрыть. Это целевой контракт M01, а не утверждение о приёмке текущего runtime. Источники: [MenuPage.vue](../../src/pages/MenuPage.vue), [MenuReorderPanel.vue](../../src/pages/admin/menu/MenuReorderPanel.vue), [MenuReorderRow.vue](../../src/pages/admin/menu/MenuReorderRow.vue), [MenuReorderPanel.constants.ts](../../src/pages/admin/menu/MenuReorderPanel.constants.ts).

`MenuOverview` — единственный владелец toolbar обзора и поднимает typed events создания, перехода к порядку и редактирования категорий, товаров и групп добавок. `MenuPage` владеет product-create dialog и navigation к `ProductEditPage`; `ProductEditPage` владеет edit draft, командами save/archive и leave flow. Reorder panel windows complete category subtrees и sibling products через spacer ranges, сохраняя логические position/total для строк. Источники: [MenuOverview.vue](../../src/pages/admin/menu/MenuOverview.vue), [ProductEditPage.vue](../../src/pages/ProductEditPage.vue), [useVirtualSiblingRows.ts](../../src/pages/admin/menu/composables/useVirtualSiblingRows.ts).

Цель редактирования товара: закреплённые действия «Отмена» и «Сохранить изменения» стоят в одном горизонтальном ряду у правого края от 320 px, в этом порядке, без переноса или обрезки подписей. Последняя цена, публикация и архив доступны прокруткой полностью над действиями и нижней навигацией; в конце формы нет избыточного пустого промежутка. Поясняющий текст о сохранении цен и настройке их доступности не дублирует поля и действия. `ProductEditForm` владеет компоновкой действий, `PriceChoicesEditor` — отображением цен, `ProductEditPage` сохраняет владение черновиком, командами и переходом; общие `AdminActionGroup` и `AdminButton` остаются единственными примитивами действий. Семантика save/cancel/archive, dirty, pending, validation и цен не меняется. Это целевой контракт P01, требующий независимой визуальной проверки итогового UI. Источники: [ProductEditForm.vue](../../src/pages/admin/menu/product-edit/ProductEditForm.vue), [PriceChoicesEditor.vue](../../src/pages/admin/menu/product-edit/PriceChoicesEditor.vue), [ProductEditPage.vue](../../src/pages/ProductEditPage.vue), [AdminActionGroup.vue](../../src/shared/ui/admin/admin-action-group/AdminActionGroup.vue), [AdminButton.vue](../../src/shared/ui/admin/admin-button/AdminButton.vue), [процесс визуальной работы](../../../docs/40-quality/Validation-strategy.md#процесс-визуальной-работы).

Цель обзора меню O01: один заголовок «Меню», явные действия «Добавить категорию», «Добавить товар» и спокойное «Изменить порядок». При тесном контейнере действия занимают отдельные полноширинные строки с однострочными подписями; короткие существительные и прежняя обязательная пара заменены по замечанию пользователя. Создание товара недоступно без категории; порядок недоступен, если нельзя переместить ни категории, ни соседние товары. Раздел «Категории» и отделённые на 24 px «Группы добавок» не повторяют общие количества и нулевые состояния. У каждого раздела одно действие создания, пустота обозначена один раз. Произвольного зелёного выделения новой категории нет; её автоматическое раскрытие сохранено. Результаты серверных операций принадлежат корневым уведомлениям. Это целевой контракт, требующий независимой проверки; наличие исходников не означает приёмку. Владельцы: [MenuOverview.vue](../../src/pages/admin/menu/MenuOverview.vue), [MenuPage.vue](../../src/pages/MenuPage.vue).

`AddCategoryDialog` и `EditCategoryDialog` владеют только диалоговым состоянием и поднимают create/save/archive actions. `CategoryFormFields` отображает общие поля, а `useCategoryDraft` владеет нормализованным baseline, valid и dirty. `MenuPage` остаётся владельцем API-команд, pending/error archive state и закрытия редактора только после подтверждённой архивной команды. Источники: [AddCategoryDialog.vue](../../src/pages/admin/menu/AddCategoryDialog.vue), [EditCategoryDialog.vue](../../src/pages/admin/menu/EditCategoryDialog.vue), [MenuPage.vue](../../src/pages/MenuPage.vue).

Цель выбора цен при создании товара: до 599 px пустое состояние показывает сообщение целиком, а каждая добавленная цена занимает компактные две строки без горизонтальной прокрутки. В первой строке видны ручка порядка, название порции и цена; во второй — обозначенное «В продаже» состояние с переключателем, редактирование и удаление. Длинное название может занимать две строки с обрезкой; полное значение доступно при редактировании через существующий `PriceChoiceDialog`. Последняя строка доступна прокруткой над действиями канонического диалога. От 600 px сохраняется таблица с теми же столбцами. `AddProductDialog` владеет локальным порядком, доступностью и черновиком цен; `PriceChoiceDialog` — вводом цены и порции; `AdminDialog` — прокруткой и действиями диалога. Сохранение, валидация, disabled/pending и payload не меняются. Нативные кнопки редактирования и удаления и их колонка резервируют область по G54: не менее 48 × 48 px ниже 768 px и 44 × 44 px от 768 px без перекрытия соседей. Это целевой контракт, требующий независимой проверки итогового UI; описание целевого размера не означает приёмку текущей реализации. Источники: [AddProductDialog.vue](../../src/pages/admin/menu/AddProductDialog.vue), [PriceChoiceDialog.vue](../../src/pages/admin/menu/PriceChoiceDialog.vue), [AdminButton.vue](../../src/shared/ui/admin/admin-button/AdminButton.vue), [процесс визуальной работы](../../../docs/40-quality/Validation-strategy.md#процесс-визуальной-работы).

`AvailabilityPage` и `QueuePage` владеют API-загрузкой, stale-request защитой, query persistence и входом после `401`; экранные компоненты получают данные/статусы props и поднимают действия emits. Источники: [AvailabilityPage.vue](../../src/pages/AvailabilityPage.vue), [QueuePage.vue](../../src/pages/QueuePage.vue), [AvailabilityScreen.vue](../../src/pages/admin/availability/AvailabilityScreen.vue), [OrdersScreen.vue](../../src/pages/admin/orders/OrdersScreen.vue).

Цель загрузки доступности: три строки-заглушки `AvailabilityScreen` различимы на фоне страницы при ширине от 320 px и на широком экране. Они сохраняют высоту 72 px, заголовок, поиск и нижнюю навигацию без дополнительного текста. `AvailabilityPage` продолжает владеть загрузкой и API; состояния готовности, пустого списка, фильтра и сохранения не меняются. Это целевой контракт F-AV-01, требующий независимой визуальной проверки итогового UI. Источники: [AvailabilityScreen.vue](../../src/pages/admin/availability/AvailabilityScreen.vue), [AvailabilityPage.vue](../../src/pages/AvailabilityPage.vue), [процесс визуальной работы](../../../docs/40-quality/Validation-strategy.md#процесс-визуальной-работы).

Цель фильтров очереди: все шесть стадий видны без горизонтальной прокрутки и доступны прямым нажатием в одном или двух плотных рядах при ширине от 320 до 1440 px. Поиск по номеру и обновление очереди остаются отдельными действиями; выбранная стадия видна, поиск и фильтр продолжают передаваться владельцу `QueuePage` без изменения API и query state. `OrdersScreen` владеет компоновкой панели очереди, общий `FilterTabs` — видом и нажатием вкладок через явно выбранный режим переноса; остальные потребители сохраняют свой режим. Интерактивная область вкладок остаётся не менее 44 px от 768 px и 48 px ниже 768 px; страница не получает горизонтальную прокрутку, а контент и нижняя навигация доступны после второго ряда. Это целевой контракт Q-QUEUE-01, требующий независимой проверки итогового интерфейса, а не утверждение о приёмке текущего runtime. Источники: [OrdersScreen.vue](../../src/pages/admin/orders/OrdersScreen.vue), [FilterTabs.vue](../../src/shared/ui/admin/filter-tabs/FilterTabs.vue), [QueuePage.vue](../../src/pages/QueuePage.vue), [процесс визуальной работы](../../../docs/40-quality/Validation-strategy.md#процесс-визуальной-работы).

Диалоги создания, редактирования и удаления работают с явными `confirm/save/cancel`; отмена очищает черновик, подтверждение удаляет только после `ConfirmDialog`. Один canonical dialog shell владеет header/body/footer/actions/close/loading/scroll; `ConfirmDialog` — его semantic preset, не отдельная surface/action recipe. ## Результаты отдельных HTTP-запросов

[HTTP-клиент](../../src/shared/api/client.ts) фиксирует отдельный результат каждого фактически начатого запроса после проверки статуса и тела ответа. Вызвавший запрос владелец явно передаёт типизированный reporting через [порт операций](../../src/shared/lib/operations/operation.types.ts) и четыре API-адаптера. Отказ до отправки, локальная проверка и общий уже выполняющийся запрос не создают HTTP-результат. Ошибка обратной связи не меняет ответ API или порядок бизнес-операций. Повтор получает новый receipt; повторный выброс того же результата не создаёт второй notice.

[Runtime уведомлений](../../src/app/notifications/notification-runtime.ts) группирует равнозначные результаты по области сессии/владельца, намерению, операции, ресурсу, классификации и безопасному восстановлению. Счётчик виден в [едином floating host](../../src/shared/ui/notifications/NotificationHost.vue). Поступление нового результата не обнуляет текущие 5000 мс видимого показа. Ошибки после этой квоты перемещаются в очередь и сохраняются до закрытия либо соответствующего восстановления; успешные результаты завершают показ. Скрытая вкладка, наведение и выполняемое действие приостанавливают время соответствующей карточки. Другие видимые карточки продолжают показ. На узком экране продвижение очереди при удерживаемой карточке зависит от завершения действия или снятия наведения.

Хранятся живые ожидающие группы, активные запросы и владельцы; фиксированного предела различных незакрытых результатов нет. Закрытые/истёкшие группы и завершённые поколения освобождаются. Подтверждённое восстановление убирает устаревшее действие, сохраняя ещё не показанный отдельный результат. Чтение не подтверждает неуспешную запись. Завершившиеся после отмены владельца запросы получают нейтральный текст без старых данных и действий; собственное подтверждение выхода переживает очистку сессии. Это описание исходников, а не утверждение выполненной интеграционной или визуальной приёмки.

Повторное появление постоянной ошибки начинает очередной текущий интервал обслуживания: эквивалентные результаты обновляют счётчик без сброса накопленного времени и перестановки видимой карточки, включая hover и выполняющееся восстановление. Связь восстановления учитывает стабильный идентификатор владельца; новый экземпляр редактора не получает действия старого экземпляра. Закрытие уведомления подтверждает его просмотр, но не удаляет безопасную команду проверки заблокированного текущего черновика.

Общий `AdminButton` имеет необязательное `presentation: control | row` с прежним `control` по умолчанию. `row` владеет прямоугольной прозрачной поверхностью, спокойным hover, выравниванием и переносом, отступами и нативной областью 44/48 px. Потребители категории, товара, группы добавок и полного названия в порядке только компонуют содержимое; обычные варианты и compact сохраняются. Источник: [AdminButton.vue](../../src/shared/ui/admin/admin-button/AdminButton.vue).

`PageShell` сохраняет прежний `contentSpacing: default` и отступ содержимого 24 px. Только меню и эквивалентные экранные истории выбирают `none`: заголовок больше не компенсирует этот отступ отрицательными значениями. Узкая панель высотой 52 px намеренно отменяет только известные верхнее и боковые поля оболочки 16 px, чтобы сохранить полный край панели.
