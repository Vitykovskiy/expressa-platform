# Владельцы UI и состояния back-office

## Граница и источники

[Контракт сотрудника](../../../docs/50-interfaces/Back-office-UI.md),
[ADR-012](../../../docs/20-architecture/ADR/ADR-012-back-office-source-contract.md)
и [технический DoD](../../../docs/80-conventions/Code-Definition-of-Done-back-office.md)
задают требования. Эта нота описывает текущую реализацию. Наличие кода,
ручные наблюдения исполнителя, независимая проверка и пользовательская приёмка
различаются: полный интегрированный результат ещё требует независимой проверки
и development-поставки.

Визуальный источник — Expressa Admin, файл `ZAOqxmGZksdKhQwEjaOrHG`.
Текущая навигация администратора использует 36:195/39:71, бариста —
36:215/39:83; исходные активные и неактивные SVG экспортированы без перерисовки.
Структура доступности — 40:507/40:1689, меню — 40:869/40:1937,
пользователей — 40:1075/40:2209, настроек — 40:1565/40:2651.
Источники карточек заказов и диалогов принадлежат их компонентам и текущим
пакетам реализации; старый UI не восстанавливался из Git.

Приём новых заказов и отдельные ценовые варианты используют существующие
группы, фильтры и строки переключателей доступности. Тихие действия выхода,
уведомлений и перехода к выбранному уведомлению встроены в оболочку;
отдельной страницы уведомлений, темы, feed или значка состояния нет.
Это композиция по G3/U007, а не утверждение о наличии отдельного нового
кадра Figma. На мобильном управление учётной записью расположено в шапке,
на экране заказов оставляет место существующему обновлению.

`pages` компонуют сценарий; `app/staff/StaffScreen` соединяет рабочие страницы
и их lifecycle. `widgets/staff` владеет адаптивным layout и role-specific ссылками.
Layout не импортирует страницы, app, store, HTTP или native protocol;
он передаёт исходное событие клика экрану. Экран помещает в default slot сначала
`NotificationsDialog`, затем существующий `.staff-content`; его ref, стили
и фокус остаются у экрана. Граница определена в
[ADR-014](../../../docs/20-architecture/ADR/ADR-014-back-office-composition-and-current-entry.md#экран-и-layout).
Направление зависимостей: `app -> pages -> widgets -> features -> entities -> shared`.
Ни один клиент не импортирует исходники другого приложения.

## Навигация и идентичность

Отсутствующий `section` означает заказы; `catalog` виден как «Меню».
Допустимы также `orders`, `availability`, `users`, `settings`. Неизвестный,
пустой или дублированный раздел показывает отказ, сохраняя исходный URL.
App хранит текущий URL как реактивный снимок и передаёт его staff-экрану.
Ссылки разделов и фонового сообщения строятся из этого снимка, сохраняя
прочие параметры и hash после popstate; обычный клик использует history,
модифицированный клик сохраняет нативную семантику ссылки.
Бариста по прямому адресу административного раздела видит отказ без его чтения.

Неактивные страницы отсутствуют в DOM. Их обычные чтения и опрос прекращаются;
уже отправленная команда и сверка её исхода остаются у владельца. Возврат
сохраняет draft, выбор и scroll только в памяти разрешённого сеанса.
Каталог сохраняет страницу через KeepAlive, настройки — draft в store.
Смена идентичности/роли/token уничтожает также сохранённый редактор.
Поздний ответ прежнего контекста не публикуется.

Телефон, OTP и access token не пишутся в URL или browser storage.
Restore использует серверную cookie. Только подтверждённый logout204 завершает
выход; неопределённый выход не подменяется успехом. 401/403 защищённой операции
передаются общему владельцу сеанса. Вход сохраняется отдельно через KeepAlive,
не забирая фокус у активного рабочего раздела.

## Команды и неопределённость

Отклонение заказа следует утверждённой форме `pristine → dirty → pending`:
пустая причина блокирует отправку, введённая непустая причина разрешает её.
Во время отправки поле и действия заблокированы. Пока открыто подтверждение
отклонения, обычное чтение списка и выбранного заказа приостановлено:
фоновое обновление не должно поглощать доступное нажатие.
Подтверждённый ответ закрывает диалог и обновляет заказ. Ошибка сервера или
неполученный ответ показываются одной `SourceToast`; причина сохраняется,
форма возвращается в `dirty`. Для отклонения нет отдельной сверки результата
или автоматического повтора записи; актуальные данные можно получить обычным
обновлением страницы. Эти изменения по U013/U014 не меняют права, сброс
сеанса, серверную проверку стадии или прежнюю сверку других команд.

Нет клиентского CRUD, фиктивных строк или автоматического повтора записи.
Команда подтверждается только ожидаемым корректным ответом своего объекта.
Чтение после неизвестного исхода показывает текущее состояние и не доказывает
авторство. Старый draft/proof не переписывается результатом такого чтения.
Неудачный refresh сохраняет ранее подтверждённые данные с явной неактуальностью;
неудачная первая загрузка не становится пустым списком.

Доступность отображает категорию, товар и всегда видимые вложенные размеры.
Маппер различает сохранённый флаг, фактическую доступность и причину блокировки;
store находит текущую вложенную цель по type/id. После каждой подтверждённой
записи перечитывается вся доступность. При неудачном чтении сохранённая
иерархия остаётся видимой и неактуальной; ручное обновление только читает.
Неизвестная запись не повторяется. Изменение каталога помечает доступность
stale; текущая команда сохраняется до разрешения. Intake сохраняет реальное
nullable время и автора без видимой подписи UTC.

Обратная связь активного сценария принадлежит его странице. Оболочка выводит
фоновые сообщения только вне исходного раздела с одной ссылкой возврата;
истечение сеанса использует исходный SourceToast 74:705/74:706.
Подробные HTTP и push-границы — в [интеграционной ноте](staff-read-slice.md).

Правила пустых цен S/M/L, сохранения единственной опции и подтверждения
исключаемых ID принадлежат
[ADR-012](../../../docs/20-architecture/ADR/ADR-012-back-office-source-contract.md#одно-заполненное-значение-размера).
Редактор использует одну общую проверку цен для доступности сохранения и
построения команды; видимая форма не хранит вторую ценовую политику.

Единственный catalog-editor владеет отдельными черновиками категории/группы
и товара/опции, версиями подтверждения и неизвестным результатом. Категория
показывает все выбранные группы через мультиселект; группа — имя и флаг
одиночного выбора. Опция редактируется отдельным диалогом с группой, именем и
ценой. Продукт не имеет собственных групп. API-граница и сервер владеют
проверкой и сохранением, а не компоненты полей.

Представление времени заказа принадлежит существующему orders presenter;
подписи настроек — SettingsFields/SettingsRecovery; timestamp доступности —
availability.mapper. Метка UTC не выводится пользователю, техническая основа
и значения API не меняются. Полный staff-номер и его фильтры не сокращаются.
