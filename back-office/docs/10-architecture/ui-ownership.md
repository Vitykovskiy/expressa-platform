# UI ownership back-office 2.0

Контракт задаёт требуемый результат нового UI, не подтверждает соответствие
runtime. Основание дополнено session/OTP и очередью/деталями и lifecycle-командами; независимая приёмка остаётся открытой. Пользователь разрешил продолжение. Предыдущая версия не
используется как референс или источник восстанавливаемого кода.

## Владельцы основания

Пути ниже действующие; их размещение определено в [code layout](../80-conventions/code-layout.md).

| Область                   | Владелец                         | Граница                                                                                                             |
| ------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Tokens и глобальные стили | `src/shared/styles/`             | Сырые значения определены один раз; semantic roles поддерживают обе темы; компоненты не создают собственную палитру |
| Определения темы Vuetify  | `src/shared/config/`             | Чистая конфигурация и фабрика; нет отдельного изменяемого предпочтения темы                                         |
| Выбор светлой/тёмной темы | `src/app/`                       | Единственный владелец предпочтения; CSS, Vuetify и Storybook отражают один выбор                                    |
| Базовый компонент         | `src/shared/ui/`                 | Представление, локальное взаимодействие, типизированные props/events/slots; нет API и бизнес-состояния              |
| Каталог и workbench       | `.storybook/` и соседние истории | Потребление публичных контрактов, ручные состояния и демонстрация композиции; нет бизнес-реализации                 |

Начальный выбор темы, сохранение предпочтения, token values, размеры и
перечень компонентов описаны в [дизайн-системе](design-system.md).
Не создавать параллельную тему каталога или независимую копию UI-компонентов.

## Видимый контракт

Пользователь просит современный минималистичный интерфейс для опытного
сотрудника, без лишних статичных информационных сообщений. Подсказка
допустима там, где нужна для конкретного решения, ошибки или восстановления;
постоянные поясняющие banners не заменяют ясный контроль и иерархию действий.
Новая палитра, геометрия и композиция не наследуются от старого UI.

Интерактивный компонент сохраняет нативную семантику, доступное имя,
клавиатурный доступ, видимый focus и корректный disabled. Поле имеет связанную
метку; ошибка относится к своему полю или действию. Состояние не передаётся
одним цветом. Dialog управляет фокусом при открытии, удерживает его внутри
модального контекста и возвращает к инициатору после закрытия. Ненужное
движение отключается при `prefers-reduced-motion`.
UiDialog отключает анимацию содержимого и встряхивание persistent-диалога
при Escape или нажатии на подложку для всех предпочтений движения.

Обе темы должны сохранять контраст текста WCAG AA: 4.5:1 для обычного текста,
3:1 для крупного. Контраст, focus, длинный русский текст, состояния загрузки,
ошибки и недоступного действия проверяются в выбранных компонентных историях
и композиции после последних изменений. Размеры, плотность и ширины
определяются наблюдаемыми критериями UI/UX-решения, не случайными значениями
из снимков референсов.

## Бизнес-граница

Полные staff-результаты, роли и инварианты принадлежат
[продуктовому контракту](../../../docs/50-interfaces/Back-office-UI.md).
Точные HTTP-схемы принадлежат
[OpenAPI](../../../backend/openapi/openapi.json), их здесь не дублируют.
Сценарий владеет запросами, преобразованием внешних данных,
конкуренцией действий и восстановлением ошибки; shared UI получает модель
представления и сообщает пользовательское действие.

Действующие владельцы session, OTP, URL и order-read описаны в [staff slice](staff-read-slice.md). Workbench не доказывает соответствие API. Lifecycle-команды реализованы и частично наблюдены в рабочем staff-runtime; [точный объём наблюдений](staff-read-slice.md#граница) не закрывает полный набор критериев и независимую приёмку. Каталог и доступность имеют отдельных владельцев.

[Установка рабочего приложения](pwa-installation.md) описывает static manifest
и новые public-иконки. Предпочтение темы остаётся у app; OS branding фиксирован
светлой палитрой. Browser-native установка и запуск не приняты. Текущий
push-only worker, opt-in и click реализованы в исходниках; native/API/UI
поведение после этих правок не наблюдено и не принято.

## Уведомления бариста

`app/App.vue` соединяет session, ожидаемые worker URL/scope, уведомления и
обычную URL-навигацию. `entities/notification/` владеет приватными native
proof, association/version и исходной операцией; `features/notifications/`
получает модель и события, владеет только открытием и возвратом фокуса.
`shared/browser/web-push.ts` выполняет native операции без business API.
Точная реализация и ограничения описаны в [staff slice](staff-read-slice.md#уведомления-и-logout).

Тихое «Уведомления» доступно только Barista после темы перед выходом.
Dialog показывает назначение «Сообщать о новых заказах», состояние,
«Закрыть» первым и не более одного основного действия. Первое unready
«Включить уведомления» только подготавливает native регистрацию/ключ;
после готовности нужен новый явный жест. Permission/subscription не
подтверждают серверное подключение или доставку. Неизвестная отправка
сохраняет исходный контекст; явная проверка показывает текущую привязку
отдельно, «Завершить проверку» освобождает только локальную проверку.

UiDialog сохраняет default `restoreFocus: true`; notification feature
использует `false` без activator и публичный `closed`. Возврат принадлежит
текущему инициатору только при сохранённых identity/section/lifetime и
отсутствии нового фокуса. Поздняя готовность не получает autofocus.
Клик в занятом workspace оставляет одну тихую «Открыть выбранный заказ»
после section nav; новый другой клик заменяет только navigation intent с
видимым пояснением и polite announcement, когда оболочка доступна.
Draft, исходная команда и modal остаются у прежних владельцев. Закрытие
modal или завершение операции само не открывает заказ.

## Доказательство и приёмка

Оперативная доступность описана в [availability slice](availability-slice.md),
administrator-категории — в [category slice](catalog-categories-slice.md),
товары и атомарные цены — в [product slice](catalog-products-slice.md),
группы и полный состав — в [modifier slice](catalog-modifiers-slice.md),
полная замена связей категории — в [association slice](catalog-associations-slice.md).
App владеет role-aware третьим разделом и соединяет catalog mutationEpoch с
узкой freshness invalidation availability. Общий optional method допускает
GET/POST/PATCH/DELETE/PUT; runtime транспорта и foundation сохранены.
Полные runtime/визуальные критерии и независимая приёмка остаются открытыми.

Исполнитель проверяет публичные контракты и применимые нетестовые команды,
лично осматривает свежий рендер. Независимый reviewer проверяет код,
документацию, живой UI и снимки по
[UI DoD](../../../docs/40-quality/Definition-of-done.md) и
[стратегии](../../../docs/40-quality/Validation-strategy.md).
Каталог, успешная сборка и самооценка не принимают дизайн.
Пользователь разрешил продолжение; прежние пробелы наблюдения/skills и независимая приёмка основания этим не закрываются.
Автоматизированные тесты не создаются, не меняются и не запускаются;
после приёмки они требуют отдельного прямого запроса пользователя.
