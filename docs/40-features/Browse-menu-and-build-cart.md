# Просмотр меню и сбор корзины

## 6. Пользовательские сценарии

### 6.1. Просмотр меню

1. Гость открывает front-office по публичной ссылке.
2. Приложение загружает состояние приёма новых заказов и меню.
3. Клиент выбирает категорию.
4. Клиент открывает товар.
5. Для напитка приложение заранее выбирает размер `M`, если он доступен, иначе — доступный размер напитка; для остальных товаров выбор размера отсутствует.
6. Приложение заранее выбирает обязательные добавки по умолчанию; клиент при необходимости меняет размер, добавки и количество.
7. Приложение показывает итоговую цену позиции.
8. Клиент добавляет позицию в корзину.

Сценарий использует публичный `GET /api/v1/public/menu`. Экран обрабатывает загрузку, ошибку с повтором и пустой результат; предупреждение о приёме новых заказов читается из ответа. Переходы категория → товар и возврат сохраняют позицию прокрутки. Оформление использует отдельный `POST /api/v1/orders`; история не входит в этот реализованный сценарий.

- **BR-001.** Публичное меню доступно гостю.
- **BR-015.** Только напитки могут иметь один или несколько размеров из `S`, `M`, `L`; остальные товары продаются по одной цене без выбора размера.
- **BR-023.** Для напитка по умолчанию выбирается доступный размер `M`; если его нет, выбирается доступный размер напитка. Карточка товара открывается с корректной конфигурацией.

### 8.3. Корзина

- **FR-CART-001.** Корзина хранится локально в браузере front-office.
- **FR-CART-002.** Карточка напитка открывается с заранее выбранным доступным размером: `M`, если он доступен, иначе — другим доступным размером. Обязательные добавки также выбраны заранее. Клиент может сразу добавить товар либо изменить конфигурацию.
- **FR-CART-003.** Клиент изменяет количество позиции.
- **FR-CART-004.** Клиент удаляет позицию.
- **FR-CART-005.** Повторное добавление идентичной конфигурации увеличивает количество.
- **FR-CART-006.** Корзина показывает цену каждой позиции и общий итог.
- **FR-CART-007.** Перед оформлением backend выполняет полную проверку товаров, цен и доступности.
- **FR-CART-008.** При изменении цены front-office показывает актуальный итог и запрашивает повторное подтверждение.
- **FR-CART-009.** При выключенной доступности front-office выделяет затронутые позиции и предлагает обновить корзину.
- **FR-CART-010.** Максимальное количество одной конфигурации ограничено backend значением 20.
- **FR-CART-011.** Корзина, собранная до авторизации, сохраняется после успешного входа.
- **FR-CART-012.** При явном выходе из учётной записи front-office очищает локальную корзину.

Front-office хранит отдельно каждую конфигурацию товара, объединяет только
идентичные конфигурации и восстанавливает корзину после перезагрузки и OTP-входа.
После успешного создания корзина очищается; при сетевом повторе сохраняются её
состав и ключ идемпотентности до получения результата.
