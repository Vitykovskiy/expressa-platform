# Definition of Done для UI

Эта нота задаёт gate завершённости UI-задачи и применяется ко всему Vue UI-коду
`front-office` и `back-office`, включая runtime UI и Storybook. Детальные
правила Vue и Vuetify определяет [[Vue-code-style|стиль
Vue-кода]].

## Gate

- Изменение сохраняет границы двух независимых продуктов, `pages`, `shared`,
  `shell` и Storybook по [[20-architecture/ADR/ADR-006-runtime-ui-and-storybook-boundaries|ADR-006]].
- Изменённый Vue/Vuetify-код соответствует
  [[Vue-code-style|стилю Vue-кода]]; истории остаются отдельным
  демонстрационным слоем и импортируют готовый runtime-код.
- Изменённое UI-поведение соответствует
  [[UI-accessibility|требованиям доступности и взаимодействия]].
- Выполнены применимые проверки из
  [[Validation-strategy|стратегии проверки]]: форматирование, lint,
  typecheck, сборка Storybook, истории и браузерная проверка.
- После разработки пройдена обязательная браузерная UI-приёмка по
  [[Validation-strategy#Браузерная UI-приёмка|стратегии проверки]]. Без свежего
  положительного вердикта UI-задача не завершена.
- Diff не содержит несвязанных правок, временного кода или отключённых проверок.

## Подтверждение

В отчёте задачи указаны выполненные команды, их результат и непроведённые
проверки с причиной. Невыполненный обязательный пункт gate, кроме браузерной
UI-приёмки, требует отдельного зафиксированного решения. Браузерная UI-приёмка
не допускает пропуска отдельным решением или оформлением риска: отсутствующий,
неуспешный, устаревший либо самоподтверждённый вердикт означает непринятие.

## Браузерная UI-приёмка

Разработчик собирает доказательства, а `reviewer_owner` независимо просматривает
живой интерфейс и каждый снимок, владеет циклом исправления и повторной проверки.
Самоприёмка, отсутствующие или устаревшие доказательства, а также любой
подтверждённый UI/UX-дефект означают провал. `integration reviewer` не может
дать `approved` без свежего положительного вердикта. Правила состава
доказательств, повторов и блокировки определяет
[[Validation-strategy#Браузерная UI-приёмка|стратегия проверки]].
