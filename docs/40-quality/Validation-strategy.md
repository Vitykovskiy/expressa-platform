# Стратегия проверки

Это стратегия проверки всего Vue UI в `front-office` и `back-office`, а не
отчёт о выполненных тестах. Требования взаимодействия и доступности задаёт
[[UI-accessibility|одноимённая quality-нота]]. Playwright даёт свидетельство
наблюдаемого поведения, но не определяет требования и не заменяет источник
истины.

Admin и Customer независимы: каждый владеет собственными design tokens,
runtime UI и Storybook; общих UI/npm-пакетов и импортов между продуктами нет.

## Обязательные уровни

- Сборка, typecheck и lint — в каждом изолированном npm-проекте.
- Модульные тесты — для логики с самостоятельными входами и выходами.
- Интерактивные проверки Storybook и проверки доступности — для соответствующих состояний историй.
- Playwright в реальном браузере — для ключевых пользовательских потоков и наблюдаемого вида.
- Проверки доступности и взаимодействия выполняются в границах [[UI-accessibility|профильной quality-ноты]].

## Ширины браузера

Проверяйте `479`, `480`, `767`, `768`, `1023`, `1024` px там, где экран или
компонент зависит от ширины. Для Admin критична граница `768`; для Customer —
границы `480` и `1024`. Визуальные эталоны находятся рядом с Playwright-тестами
каждого клиента.

## Выполнение

Применимые команды определены в `front-office/package.json` и
`back-office/package.json`: форматирование, lint, typecheck, unit-тесты, сборка
и проверка каталога Storybook, interaction, accessibility, visual и e2e.
