# Критерии чистого кода

Это обязательные критерии приёмки нового и изменяемого авторского кода
Expressa: backend, front-office, back-office и общих технических файлов.
KISS, DRY, все пять SOLID и C1–C6 применяются по содержанию изменения.
Нарушение применимого критерия блокирует приёмку кода. Исключение требует
прямого указания пользователя; неприменимость объясняется отсутствием
механизма, а не сложностью исправления.

Стандарт дополняет технические DoD
[backend](Code-Definition-of-Done-backend.md),
[front-office](Code-Definition-of-Done-front-office.md) и
[back-office](Code-Definition-of-Done-back-office.md).
Он задаёт требуемое состояние, а не подтверждает соответствие существующего
репозитория. Нетронутый код не мигрируется вне связанной задачи. В затронутом
участке устраняются препятствия чтению и сопровождению, необходимые для
текущего результата; понятный код не перестраивается ради формы.

## Происхождение и адаптация

Основа — текущая семья Code Style и Definition of Done из каталога
`docs/80-conventions` репозитория `barsim-4.0-frontend`, прочитанная
2026-10-20 по запросу пользователя. HEAD исходника:
`4736dc0db446b535d4177a25844d7c63138aa4a9`.
У Code-style-Modules на момент чтения была локальная правка даты и пути
импорта в Angular-примере; этот пример не перенесён. Эта нота является
самостоятельной нормой Expressa, зависимости от соседнего checkout нет.

| Семья исходных нот                                           | Адаптация для Expressa                                                                                                                                                                  |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Code-style, Code-style-Principles, Definition-of-Done        | Обязательность KISS, DRY, всех SOLID и C1–C6, область изменения, доказательства и блокировка приёмки.                                                                                   |
| Code-style-Naming, Code-style-Comments, Code-style-Functions | Предметные имена, связность, аргументы, порядок, эффекты, русские комментарии и удаление шума. Форматы имён остаются локальными.                                                        |
| Code-style-Types, Code-style-Modules                         | Явные значения, предпосылки, точность, ответственность и зависимости. Размещение деклараций сохранено по DoD Expressa; классы и приватные методы Angular не навязаны SFC и composables. |
| Code-style-Contracts                                         | Все O/L/I перенесены с условиями, включая структурные контракты и обоснованную неприменимость L.                                                                                        |
| Code-style-Angular, Code-style-State                         | Намерение контрактов компонентов, владельца и срока жизни перенесено на Vue/Pinia. Signal API, OnPush, Facade и provider-механика не переносятся.                                       |
| Code-style-Async                                             | Семантика актуальности, отмены, мутаций, контекста и ресурсов сохранена без обязательных Observable и RxJS-операторов.                                                                  |
| Code-style-Data                                              | Граница доверия, чистый маппинг, отсутствие и ошибки сохранены. RestService, toast, диагностика и Barsim ADR не назначают владельцев Expressa.                                          |
| Code-style-Forms, Code-style-Styles                          | Сохранены смысл значений формы, сброс, валидация и единый владелец представления. Конкретные библиотеки форм, tokens и стили определяют Expressa-контракты.                             |

Ограничения Barsim на специализированную доступность не переносятся:
действуют требования Expressa. Java-приёмы, числовые советы книги и TDD
не становятся отдельными требованиями. Стек, автономность приложений,
[ADR-011](../20-architecture/ADR/ADR-011-back-office-clean-slate.md)
и абсолютные ограничения [AGENTS](../../AGENTS.md) сохраняются.
