# Работа с Git и поставка

## Применимость и полномочия

Нота связывает Git-результат с [границами автономности AGENTS](../../AGENTS.md#границы-автономности) и [правилами выпуска](../70-deployment/Release-and-version-compatibility.md). Поручение документационной правки само по себе не разрешает commit, push или deploy. Уже разрешённое действие выполняется в согласованных пределах без повторного запроса.

## Фактическая линия поставки

Поддерживаемая development-поставка идёт из текущего `main` по правилам выпуска. Стратегия Barsim `main/develop/task`, отдельная `develop` и tracker-префикс не переносятся в Expressa. Эта нота не вводит новую обязательную веточную схему. Перед работой учитывайте текущие branch/status и существующие пользовательские изменения; чужая работа не откатывается.

## Интеграция результата

Проверяется тот итоговый diff, который передаётся дальше. Успех двух отдельных веток не доказывает комбинацию после конфликта; повтор разрешённых проверок нужен для изменившегося входа или оставшегося критерия. Одинаковое дерево файлов может сохранить прежние актуальные доказательства, смена одного SHA сама по себе не требует повторного прогона. Результат различает изменение файлов, независимое review, пользовательскую приёмку, commit, push и поставку.

Тестовые ограничения остаются у [AGENTS](../../AGENTS.md#абсолютное-правило-до-приёмки); существующие команды — у [конфигурации](ESLint-config.md). Сообщение разрешённого коммита объясняет результат по [руководству](Commit-prefixes.md). Правило оформления не даёт разрешения выполнить Git-операцию.
