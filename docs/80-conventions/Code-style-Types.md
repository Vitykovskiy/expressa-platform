# Типы и явные значения

Применяется к новому и изменяемому авторскому коду по [общему стандарту](Clean-code.md). Приёмка — [общий DoD](Definition-of-Done.md).

Все примеры ниже учебные; их виртуальные файлы и контракты заданы в тексте, это не API или файлы Expressa.

## Контракт значения — C5

Входы, результаты, режимы, ошибки и допустимое отсутствие явны в типах
или предметном контракте. `any`, assertion и подавление ошибки типов
не заменяют проверку внешнего значения. Вывод TypeScript сохраняется, если
не теряет публичное обещание; производные аннотации не дублируются.
Размещение именованных типов и констант задают контурные DoD:
`*.types.ts` и `*.constants.ts`. Новая одноразовая именованная форма без пользы
не вводится.

Новые `@ts-ignore` и `@ts-nocheck` запрещены. Локальный `@ts-expect-error`
допустим только для подтверждённого ограничения с содержательным объяснением
причины. Non-null assertion `!` требует локально подтверждённого основания;
он не устраняет допустимое отсутствие из контракта. Конкретные настройки
строгости и lint определяет изменяемое приложение; Barsim severity и
числовые ограничения комментариев не объявляются настройками Expressa.

Для алгоритма установлены единицы, диапазон, порядок, точка отсчёта и нужная
уникальность. Первая запись не доказывает единственность. Для чисел определены
точность и округление; для даты — календарная дата либо момент и нужная зона.
Денежные вычисления следуют действующему предметному контракту представления
и округления; молчаливое предположение о точности `number` недопустимо.
Стандарт не выбирает новую библиотеку или формат API.

`null` и `undefined` допустимы как предусмотренное отсутствие, которое
отличается от ошибки. Подтверждённый default задаёт владелец политики;
низкий уровень не угадывает его по неописанному sentinel. Подстановка
не скрывает повреждённые обязательные данные. Семантически равные формы
возврата не переписываются ради единообразия.

Магический литерал скрывает правило, единицу, статус, ключ, режим, ограничение
или таймаут; его смысл выражается предметным типом, константой или настройкой.
Очевидные локальные `length === 0` и `index + 1`, а также значение явного
внешнего контракта допустимы. Технический ключ имеет стабильное имя и реального
потребителя; UI-текст не определяет поведение программы. Метаданные содержат
только используемые поля.

## Пример отсутствия и некорректного режима

**Пример E09.** Иллюстративный контракт выбирает `draft` либо `published`; отсутствие выбранного режима (`null`) разрешено, неизвестная строка ошибочна. В `publication.types.ts`:

```typescript
export type PublicationMode = "draft" | "published";
```

Антипример `publication-mode.mapper.ts` обещает контракт через assertion и тайно заменяет отсутствие режимом:

```typescript
import type { PublicationMode } from "./publication.types";

export function parsePublicationMode(value: string | null): PublicationMode {
  return (value ?? "draft") as PublicationMode;
}
```

Исправление в том же виртуальном файле:

```typescript
import type { PublicationMode } from "./publication.types";

export function parsePublicationMode(
  value: string | null,
): PublicationMode | null {
  if (value === null) {
    return null;
  }

  if (value === "draft" || value === "published") {
    return value;
  }

  throw new Error("Неизвестный режим публикации");
}
```

Здесь строки — явно перечисленные значения объявленного контракта. Допустимые режимы сохранены; отсутствие больше не становится черновиком, ошибочная строка отклоняется. Исправление восстанавливает заявленный контракт и требует соответствующего разбора результата у потребителя. Выдуманный числовой флаг вроде `1` без имени режима скрыл бы то же обещание. Пример не задаёт режимы реального API.

## Возврат и конфигурация

Команда без результата использует `return;` для раннего выхода. Функция со значением может вернуть `undefined`, когда это предусмотренное отсутствие; публичный тип и результаты веток сохраняются. Семантически равные формы не переписываются ради единообразия.

Конфигурация принадлежит владельцу политики, передаётся явно при необходимости и не становится environment-настройкой автоматически. Неописанный sentinel не заменяет договорённость.

## Наблюдение при приёмке

Сравните допустимые входы, отсутствие, ошибку и результаты веток с контрактом; для алгоритма установите единицы, границы, точность и нужную уникальность. Assertion, скрывающий повреждённый вход, либо выдуманный default блокируют приёмку.
