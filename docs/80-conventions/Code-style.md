# Карта Code Style

Начните с [области и обязательности](Clean-code.md), затем прочитайте [принципы](Code-style-Principles.md), затронутую область и её предметный контракт. [Общий DoD](Definition-of-Done.md) задаёт приёмку; [INDEX](INDEX.md) добавляет контуры и виды изменения. Учебные примеры объявляют собственные предпосылки и не задают API продукта.

## Области кода

| Область       | Подробный владелец                                                                    |
| ------------- | ------------------------------------------------------------------------------------- |
| Выбор решения | [Принципы](Code-style-Principles.md): KISS, DRY и текущие потребители.                |
| Имена         | [Имена](Code-style-Naming.md): C1, словарь и различимость.                            |
| Комментарии   | [Комментарии](Code-style-Comments.md): C6, причины и актуальность.                    |
| Функции       | [Функции](Code-style-Functions.md): C2–C4, аргументы, порядок и эффекты.              |
| Значения      | [Типы](Code-style-Types.md): C5, отсутствие, литералы, точность и конфигурация.       |
| Модули        | [Модули](Code-style-Modules.md): SOLID-S/D, инварианты, файлы и зависимости.          |
| Контракты     | [Варианты](Code-style-Contracts.md): SOLID-O/L/I и наблюдаемые обещания.              |
| Компоненты    | [Vue](Code-style-Vue.md): маршрут к каноническому Vue style и идентичности элементов. |
| Состояние     | [Состояние](Code-style-State.md): владелец, контекст и черновик.                      |
| Асинхронность | [Сценарии](Code-style-Async.md): актуальность, отмена, мутации и ресурсы.             |
| Данные        | [Внешние данные](Code-style-Data.md): unknown, проверка, маппинг и ошибки.            |
| Формы         | [Формы](Code-style-Forms.md): типизированные значения, сброс и валидация.             |
| Стили         | [Стили](Code-style-Styles.md): маршрут к продуктовым tokens и исключениям CSS.        |

## Процесс и исполнимая конфигурация

- [Общая приёмка](Definition-of-Done.md) и все затронутые контурные DoD из [INDEX](INDEX.md).
- [ESLint и Prettier](ESLint-config.md): существующие команды, охват и ограничения.
- [Git workflow](Git-workflow.md) и [сообщения коммитов](Commit-prefixes.md).
- [Разрешённые действия](Allowed-without-confirmation.md) и [требующие подтверждения](Requires-confirmation.md).
- [Карта владельцев](_MOC-conventions.md): чем различаются норма, конфигурация и факт.

Существующий [Clean-code](Clean-code.md) остаётся стабильным входом. Подробная норма сопровождается у указанного владельца; карты не образуют параллельный стандарт. Наличие документов не подтверждает соответствие всего кода.
