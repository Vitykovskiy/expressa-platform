# Функции и поток управления

Применяется к новому и изменяемому авторскому коду по [общему стандарту](Clean-code.md). Приёмка — [общий DoD](Definition-of-Done.md).

Все примеры ниже учебные; их виртуальные файлы и контракты заданы в тексте, это не API или файлы Expressa.

## Связность и аргументы — C2

Функция выполняет одну связную операцию на уровне абстракции своего имени.
Координация не смешивается с деталями сериализации, хранения или отображения
чужого владельца. Самостоятельный предметный шаг, инвариант или несколько
связанных эффектов выделяются, когда это облегчает чтение. Очевидный callback,
одно присваивание или вызов не получают helper автоматически.

Сложное выражение разделяется на промежуточные значения с предметными именами,
когда они раскрывают этапы, единицы и границы. Значение объявляется рядом
с первым использованием в минимальной области; переменная-прокси без пользы
не нужна. Автор и reviewer могут объяснить алгоритм и его предпосылки.

Смысл однотипных позиционных аргументов понятен из вызова. Неоднозначность
устраняется именем команды, связным объектом или существующим типом.
`save(true)` скрывает выбор публикации; `saveAndPublish()` раскрывает его.
`setArchived(true)` уже выражает предметное логическое значение и не требует
двух команд. Boolean не запрещён; объект не маскирует несвязанные входы.

### C3 — последовательный поток управления

Основной сценарий читается последовательно. Ранний отказ используется,
когда упрощает поток; небольшая вложенность допустима, когда яснее выражает
условия. Упрощение сохраняет порядок проверок, результаты, ошибки и эффекты.
Вложенные тернарные операторы и цепочки callbacks не маскируют вложенные `if`.
Тернарный оператор выбирает синхронное значение; асинхронный сценарий задаётся
явной веткой или предметной функцией. Каждая ветка имеет фигурные скобки и
отдельные строки в TypeScript/JavaScript, включая одно действие.
Однострочный `if` с `return` в этих языках запрещён.

Сложное предметное условие получает понятное имя, когда это проясняет решение;
очевидная проверка остаётся на месте. Двойные отрицания устраняются, естественный
ранний отказ допустим. Намеренное пустое тело цикла видно явно.
Преобразование индекса, длины или границы диапазона имеет одного владельца
и учитывает зависимые сравнения и потребителей.

Обязательная подготовка выражена входным результатом, одной командой сценария
либо явным состоянием с предусмотренным отказом. Потребитель не восстанавливает
скрытый порядок изменения внутренних полей. Для достижимых пропуска подготовки,
повтора, смены контекста и ошибки определён результат. Действующий lifecycle
сохраняется; новый wrapper или state machine автоматически не вводится.

### C4 — явные эффекты

Запрос значения и чистое преобразование не скрывают запись состояния, HTTP,
навигацию, уведомление, аудит или логирование. Команда выражает наблюдаемое
действие и находится у владельца сценария. Чистый маппер возвращает результат,
а не меняет вход как скрытый выходной параметр. Явная мутация у владельца
и framework callbacks с объявленным mutable-контрактом допустимы.
Команда может возвращать значимый результат.

Подробные требования к именам — [C1](Code-style-Naming.md), комментариям и лишнему коду — [C6](Code-style-Comments.md).

## Пример последовательного потока

**Пример E07.** Иллюстративная нормализация названия: `null` разрешён как отсутствие; пустое после `trim()` значение является ошибкой. Виртуальный `title.mapper.ts`, антипример:

```typescript
export function process(value: string | null): string | null {
  if (value !== null) {
    if (value.trim().length === 0) {
      throw new Error("Название пусто");
    }
    return value.trim();
  }

  return null;
}
```

Исправление:

```typescript
export function normalizeOptionalTitle(value: string | null): string | null {
  if (value === null) {
    return null;
  }

  const title = value.trim();

  if (title.length === 0) {
    throw new Error("Название пусто");
  }

  return title;
}
```

C1 раскрывает назначение, C2 оставляет один шаг, C3 делает порядок видимым: сначала отсутствие, затем пустота, затем результат. Входы, сообщение ошибки, результаты и отсутствие эффектов сохранены. Выделять `isEmpty` только ради единственного `length === 0` не нужно.

## Подготовка и эффект в вызове

**Учебные иллюстрации, не API Expressa.** `prepare(); save();` скрывает зависимость, если сохранение требует невыраженного внутреннего результата. При чистой подготовке `const payload = prepare(input); save(payload);` делает её явной; единая команда существующего владельца уместна, если оба шага составляют одну операцию. Для пропуска подготовки, повтора, смены контекста и ошибки прочитайте реальный контракт; новый wrapper не обязателен.

`readNames()` не должен молча очищать буфер. Если потребление действительно нужно, команда `consumeNames()` возвращает накопленные имена и явно завершает владение ими; прежний потребитель обновляется вместе с именем. Чтение без потребления сохраняет буфер. Две операции нужны только при двух текущих способах использования.

## Наблюдение при приёмке

Reviewer прослеживает вход, подготовку, каждую ветку, ошибку и эффект до потребителя. Неясная предпосылка или изменение результата при «упрощении» блокируют приёмку. Число строк и тип boolean сами по себе основанием отказа не являются.
