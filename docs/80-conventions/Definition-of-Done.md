# Общая приёмка кода

Применяется ко всем затронутым контурам и общим техническим файлам вместе с [картой стиля](Code-style.md), [backend DoD](Code-Definition-of-Done-backend.md), [front-office DoD](Code-Definition-of-Done-front-office.md) и [back-office DoD](Code-Definition-of-Done-back-office.md). Подробная норма остаётся у предметного владельца.

## Критерии и доказательства

Автор и reviewer читают изменённый код, затронутые вызовы, потребителей
и первичные контракты. Для каждого применимого критерия в существующем
результате review фиксируются источник/раздел, проверенная область и
конкретное наблюдение либо разрешённая проверка. Однородные наблюдения
можно объединить, сохранив явный охват. Отдельный шаблон отчёта не вводится.

| Критерий                  | Что должно быть подтверждено                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| KISS, DRY                 | Текущий сценарий каждой конструкции, один владелец знания, польза объединения и сохранение границ.                                      |
| SOLID-S/D                 | Причина изменения, инкапсулируемый инвариант и направление зависимостей; технические детали у своего владельца.                         |
| SOLID-O/L/I               | Использован действующий контракт вариантов, сохранены обещания подстановки, потребителю не навязаны лишние операции.                    |
| C1/C2                     | Имена и аргументы понятны в затронутых вызовах; функции связны, извлечения имеют самостоятельный смысл.                                 |
| C3                        | Видны порядок проверок и предпосылки алгоритма; сохранены ветки, результаты, ошибки и обязательная подготовка.                          |
| C4/C6                     | Эффекты явны и имеют владельца; комментарии точны, лишний код отсутствует, логические блоки читаемы.                                    |
| C5 и данные               | Различимы значение, допустимое отсутствие и ошибка; подтверждены единицы, округление, диапазон и нужная уникальность.                   |
| Состояние и асинхронность | Явны контекст запуска, срок жизни, конкурентность, cleanup и составной инвариант; поздний результат не повреждает актуальное состояние. |
| Контурные правила         | Сохранены локальные слои, размещение типов/констант, API и UI-контракты; выполнен применимый контурный DoD.                             |

Замечание содержит файл/символ, критерий, наблюдаемую проблему и минимальное
исправление. Вкусовое предпочтение или лозунг без последствия не являются
дефектом. Неприменимость объясняется конкретно: например, отсутствие
подставляемых реализаций для L. Непроверенное применимое требование остаётся
непроверенным и блокирует положительный вердикт; нарушение не объявляется
неприменимым.

Рефакторинг сохраняет установленное поведение, инварианты и совместимость.
Изменение контракта обосновывается требованием и различается со структурной
правкой. Lint, Prettier, typecheck и сборка подтверждают только свой охват;
они не доказывают читаемость, сохранение поведения или работу UI.
Результат различает чтение исходников, статические проверки, runtime
и непроведённые проверки с причиной. Независимое review не заменяет
пользовательскую приёмку; для UI сохраняется обязательный
[UI DoD](../40-quality/Definition-of-done.md).

До явной приёмки результата пользователем запрещено создавать, изменять
и запускать автоматизированные тесты. После неё любая работа с тестами
требует прямого запроса пользователя. Стандарт не вводит тесты в hooks,
CI или deployment-gate, не разрешает новые валидаторы, check scripts,
метрики и автоматизацию. Используются существующие применимые нетестовые
проверки; правила сами по себе не являются задачей аудита или рефакторинга
всего репозитория.

## Дополнительные вопросы по области

| Область                      | Наблюдение и владелец                                                                                                                                              |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Функции и значения           | Видны обязательная подготовка, порядок, единицы, точность, округление и необходимая уникальность? [Функции](Code-style-Functions.md), [типы](Code-style-Types.md). |
| Границы модулей              | Не раскрыт изменяемый инвариант, типы/константы у своего владельца, после переименования обновлены потребители? [Модули](Code-style-Modules.md), контурный DoD.    |
| Компоненты                   | Представление декларативно, контракт входов/событий минимален, идентичность списка стабильна? [Vue](Code-style-Vue.md).                                            |
| Данные и ошибки              | Нет подстановки вместо повреждённых данных, сохранены разрешённое отсутствие, причина и безопасный контекст ошибки? [Данные](Code-style-Data.md).                  |
| Состояние и запросы          | Отзыв контекста, cleanup, поздние результаты и мутации не нарушают инвариант? [Состояние](Code-style-State.md), [асинхронность](Code-style-Async.md).              |
| Форма и стили                | Сброс соответствует значению; tokens и исключения CSS принадлежат реальному продукту? [Формы](Code-style-Forms.md), [стили](Code-style-Styles.md).                 |
| Совместимость и документация | Изменённые вызовы, URL, API и импорты сохранены либо изменение контракта разрешено? Затронутые факты обновлены по [протоколу](../00-meta/Update-protocol.md).      |

## Завершение

Результат содержит фактический scope diff и доказательств, неприменимые и непроверенные критерии с причинами. Успех отдельных частей до интеграции не подтверждает итоговую комбинацию. Повтор уже успешной проверки нужен при изменившемся входе либо конкретном нерешённом критерии. Полномочия на Git-действия определяются [AGENTS](../../AGENTS.md), а существующие команды и охват — [конфигурацией проверок](ESLint-config.md).
