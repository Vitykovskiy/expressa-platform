# Модули и зависимости

Применяется к новому и изменяемому авторскому коду по [общему стандарту](Clean-code.md). Приёмка — [общий DoD](Definition-of-Done.md).

## Ответственность и зависимости — SOLID-S/D

| Принцип                      | Обязательное условие                                                                                                                                                                                                                                 |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S — одна ответственность     | Модуль объединяет код с одной предметной причиной изменения. Независимые причины и владельцы разделены. Координатор вызывает шаги одного сценария, сохраняя обязанности других слоёв. Независимые группы методов и полей требуют проверки связности. |
| D — направление зависимостей | Предметный сценарий зависит от контракта своего уровня, а не от чужих деталей транспорта, UI или хранения. Выбор реализаций остаётся у точки композиции. Общий владелец не зависит от конкретной feature ради её деталей.                            |

Владелец скрывает изменяемое представление и предоставляет операции,
сохраняющие инвариант. Getter/setter для каждого поля и pass-through методы
не заменяют инкапсуляцию. Чтение полей проверенного объекта и fluent API
не являются нарушением из-за числа точек. Временные значения вычисления
не становятся полями ради сокращения аргументов.

В backend сохраняются [слои и DI](Code-Definition-of-Done-backend.md#слои-и-внедрение-зависимостей).
В клиентах действуют их контурные DoD и локальные владельцы; Angular Facade,
root providers и RxJS-инфраструктура из исходного проекта не переносятся.
Предметные данные идут от своего владельца к представлению; заголовок,
уведомление или DOM не становятся их источником.

Файл имеет одну основную роль и предметного владельца. Функция, нужная только
одному обычному классу, остаётся его приватным методом; самостоятельная
framework-точка входа может быть отдельным функциональным артефактом.
В SFC одноразовая логика остаётся у компонента, без искусственного класса
или composable. Несвязанные декларации не собираются в общий склад типов
и констант. При переименовании обновляются потребители и удаляется старый
путь; файл-прокси только с re-export не создаётся, кроме публичного `index.ts`.

## Наблюдение при приёмке

Назовите причину изменения модуля, владельца инварианта и направление импортов. Чтение проверенной структуры не требует getter; обход изменяемого состояния владельца требует предметной команды. Размещение именованных типов и констант проверяется по контурному DoD, а форматы Vue-имён — по [Vue style](../40-quality/Vue-code-style.md#имена-комментарии-и-проверка).

## Пример границы сценария

**Учебная иллюстрация, не API Expressa.** Существующий сценарий открывает название по проверенному ID, а предметный API проверяет ответ и передаёт ошибку. Антипример `openCard(route, httpClient, endpoint)` заставляет сценарий знать структуру URL, HTTP и вид ответа. Изменение любого из них затрагивает предметное действие.

Исправление: компонент разбирает маршрут и передаёт `openCard({ id })`; существующий владелец сценария вызывает предметный API. API-адаптер сохраняет проверку/маппинг, а состояния данных, ошибки и загрузки остаются у владельца сценария. Отказ при недопустимом ID не исчезает. В backend аналогичная граница отделяет transport DTO от проверенной команды application, а application от SQL через действующий порт. Это распределение обязанностей, без обязательного нового Facade, Store или interface.

Композиция выбирает реализации через существующий механизм; NestJS DI и конструктор следуют backend DoD. Технический клиент не создаётся внутри domain/application. Обычный предметный объект создавать допустимо. Чистая функция не получает класс ради будущего полиморфизма, а наследование не используется только для доступа к константам.
