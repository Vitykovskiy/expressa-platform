# BL-0116 Клиент очереди следует каноническому API

## Результат

Клиент очереди использует staff-маршруты back-office для списка, деталей и действий стадий.

## Требуемое поведение

- В рабочем состоянии получать список через `GET /backoffice/orders`, открывать детали через `GET /backoffice/orders/{id}` и вызывать следующий разрешённый маршрут перехода; показать пустую очередь, ошибку и загрузку в Storybook.
- Маппинг ответа сохраняет номер, время, сумму, стадию, клиента, снимок и события без подмены API-маршрутов.

## Критерии приёмки

- Карточка и панель деталей показывают номер, время, сумму, стадию и сохранённый состав; состояния проверяемы на 768, 1280 и 1440 px.
- Ошибка списка либо деталей не показывает предыдущий заказ как результат нового запроса.
