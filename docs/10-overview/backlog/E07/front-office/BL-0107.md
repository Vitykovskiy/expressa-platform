# BL-0107 Клиент передаёт Idempotency-Key

## Результат

Одна попытка оформления использует стабильный ключ идемпотентности до получения результата.

## Требуемое поведение

- Создать ключ перед отправкой `POST /orders` и вложить его в заголовок `Idempotency-Key`.
- При повторе отправить тот же ключ, а для следующего оформления создать новый.

## Критерии приёмки

- Повтор после сетевой ошибки возвращает первоначальный заказ без второй записи.
- Новое подтверждённое оформление не использует ключ предыдущего заказа.
