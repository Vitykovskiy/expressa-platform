# BL-0132 История и пагинация следуют API заказов

## Результат

`GET /orders` возвращает историю от нового к старому через каноническую курсорную пагинацию API только для customer с активной сессией.

## Требуемое поведение

- Получать customer из активной сессии и возвращать через `GET /orders` только его заказы от нового к старому.
- Принимать и возвращать курсор следующей страницы по каноническому контракту API заказов.
- Гость и staff не получают данные истории.

## Критерии приёмки

- `GET /orders` возвращает customer с активной сессией только его заказы от нового к старому и курсор следующей страницы.
- Гость и staff не получают записи истории.
