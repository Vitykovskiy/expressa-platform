# BL-0132 История и пагинация следуют API заказов

## Результат

История customer загружается от нового к старому через курсорную пагинацию API.

## Требуемое поведение

- Запрашивать `GET /orders` для customer и использовать курсор следующей страницы из ответа.
- Добавлять следующую страницу без повторов и сохранять порядок новых к старым.

## Критерии приёмки

- В истории показаны номер, дата, сумма и стадия только собственных заказов.
- Переход к следующей странице добавляет более старые записи без нарушения порядка.
