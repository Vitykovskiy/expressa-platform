# BL-0133 Клиент истории и деталей заказа следует каноническим endpoints

## Результат

Клиент front-office использует API customer для истории и деталей заказа.

## Требуемое поведение

- Использовать в клиенте front-office только `GET /orders` и `GET /orders/{id}` для истории и деталей заказа.
- Перед открытием защищённых маршрутов истории и деталей дождаться восстановления сессии; гостя или staff направить в поток авторизации с безопасным внутренним `returnTo`.
- Создание заказа через `POST /orders` относится к [[../../E07/front-office/BL-0106|E07 BL-0106]].

## Критерии приёмки

- История и детали используют только методы и пути API заказов.
- Защищённые маршруты истории и деталей не открываются до восстановления сессии; после авторизации customer возвращается только на безопасный внутренний маршрут.
- Ответы истории и деталей отображаются в соответствующих экранах customer.
