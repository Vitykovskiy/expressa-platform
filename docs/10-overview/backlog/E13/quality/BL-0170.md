# BL-0170 Q-E2E связывает три приложения в одном независимом browser-сценарии

## Результат

Q-E2E подтверждает полный UI-путь от публикации меню до истории выданного заказа на подготовленной среде.

## Требуемое поведение

- После [[BL-0169|BL-0169]] связать POM и пользовательские шаги [[BL-0166|BL-0166]]–[[BL-0169|BL-0169]] в одном сквозном spec.
- Использовать только fixtures и публичные предметные методы Page/Component Objects.
- Создавать уникальные данные сценария, повторно открывать сохранённые сущности и очищать их через UI, если интерфейс поддерживает удаление.
- Актуализировать карту сценариев и связанную документацию standalone E2E.

## Критерии приёмки

- Administrator публикует меню, customer оформляет заказ, staff выдаёт его после оплаты, customer видит неизменяемый снимок в истории.
- Сценарий проходит независимо от порядка тестов и сохранённых данных предыдущего запуска; повторная проверка того же commit выполняется вручную через `Re-run jobs` в GitHub Actions.
- Выполнены все критерии standalone E2E DoD; API, БД, Web Storage, изменение сети и запуск приложений из набора не используются.
