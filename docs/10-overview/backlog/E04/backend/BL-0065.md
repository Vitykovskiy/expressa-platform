# BL-0065 Access и refresh-сессия заданы HTTP-соглашением

## Результат

Access token передаётся в Bearer-заголовке, refresh token — в HttpOnly-cookie.

## Требуемое поведение

- `POST /auth/refresh` принимает refresh-сессию из HttpOnly-cookie и возвращает новый короткоживущий access token для Bearer-авторизации.
- При успешном обновлении ротировать refresh token, обновить его хеш в `Session` и выдать новую HttpOnly-cookie.

## Критерии приёмки

- Запрос с действующей refresh-сессией получает новый Bearer access token и обновлённую refresh-cookie.
- Отсутствующая, истекшая, отозванная или не совпадающая с хешем сессия не обновляется и не выдаёт новые токены.
