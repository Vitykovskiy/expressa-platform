# BL-0071 Staff auth использует тот же канонический API

## Результат

Back-office использует тот же OTP API, но допускает только barista и administrator.

## Требуемое поведение

- Staff проходит запрос и проверку OTP через `/auth/otp/request` и `/auth/otp/verify`, затем клиент получает пользователя через `/me`.
- Открывать back-office только пользователю с ролью `barista` или `administrator`.

## Критерии приёмки

- Barista и administrator после успешной проверки получают доступ к back-office.
- Customer с действующей сессией не получает Staff-навигацию или защищённые действия.
