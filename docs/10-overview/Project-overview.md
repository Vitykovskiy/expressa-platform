# Обзор Expressa

Expressa помогает покупателю оформить заказ в кофейне без очереди у кассы. Продукт включает customer PWA, staff PWA и общий backend HTTP API.

## Продуктовый путь

1. Покупатель просматривает меню, выбирает товар и конфигурацию, собирает корзину.
2. Подтверждает телефон одноразовым кодом и оформляет заказ.
3. Бариста принимает заказ, готовит его и отмечает готовность.
4. Покупатель наблюдает состояние заказа и оплачивает его на кассе при получении.
5. Сотрудник выдаёт оплаченный заказ; покупатель может открыть историю и повторить заказ.
6. Администратор управляет каталогом, ценами, публикацией и доступностью.

Это продуктовый контракт из [ТЗ](../_sources/Expressa_MVP_Техническое_задание.md). Статус отдельных сценариев проверяйте по [сценариям](../40-features/INDEX.md), локальным картам и их исходникам; этот обзор не является актом приёмки MVP.

## Названия и границы

В customer-интерфейсе, названии установленного приложения и browser title требуется «Экспресса». `Expressa` остаётся внутренним именем репозитория, пакетов, API и staff-приложения. Это требование до независимой проверки customer build.

| Контур       | Ответственность                                                   | Вход                                      |
| ------------ | ----------------------------------------------------------------- | ----------------------------------------- |
| Backend      | Авторизация, каталог, бизнес-правила заказов, PostgreSQL, OpenAPI | [Карта](../../backend/docs/INDEX.md)      |
| Front-office | Покупатель, меню, конфигурация, корзина, история и заказ          | [Карта](../../front-office/docs/INDEX.md) |
| Back-office  | Сотрудники, очередь, доступность и административный каталог       | [Карта](../../back-office/docs/INDEX.md)  |

Три приложения находятся в одном Git-репозитории и собираются автономно по [ADR-001](../20-architecture/ADR/ADR-001-Root-repository-structure.md). Прямые импорты исходников между контурами запрещены; граница клиентов и backend — HTTP/OpenAPI.
