# Роли и доступ

Матрица задаёт требуемый продуктовый доступ, а не подтверждение реализации всех возможностей. Модель товара уточнена [ADR-008](../20-architecture/ADR/ADR-008-v3-catalog-orders-cutover.md).

| Просмотр публичного меню                                              |    ✓     |    ✓    |       ✓       |
| Оформление заказа                                                     |    ✓     |         |               |
| Просмотр собственных заказов                                          |    ✓     |         |               |

| Просмотр очереди заказов                                              |          |    ✓    |       ✓       |
| Получение push-уведомления о новом заказе                             |          |    ✓    |               |

| Управление доступностью                                               |          |    ✓    |       ✓       |

## Управление пользователями

По [ADR-012](../20-architecture/ADR/ADR-012-back-office-source-contract.md)
администратор получает список аккаунтов, создаёт пользователя, изменяет роль
и блокирует или разблокирует аккаунт. Это расширение прежнего ограничения
«сотрудники создаются только эксплуатационной командой», принятое для полного
макета по последнему запросу пользователя; не изменение исторического MVP.

Все операции доступны только активному administrator на сервере. Блокировка
и смена роли атомарно отзывают все сессии целевого пользователя и удаляют
только его push-привязки. Разблокировка не восстанавливает прежние сессии.
Нельзя заблокировать себя, понизить собственную роль или убрать последнего
активного administrator: сервер возвращает `409 USER_ACCESS_CONFLICT`.
Конкурентные изменения состава администраторов сериализуются одной блокировкой.
Действующие токены проверяются по текущим роли и блокировке в базе.

Первый administrator задаётся переменной `BOOTSTRAP_ADMIN_PHONE`.
Эксплуатационная команда `npm run staff -- upsert` остаётся способом
восстановления доступа и поддерживает `barista`, `administrator`, `customer`.
Она не снимает блокировку аккаунта неявно; смена роли также отзывает его
сессии и push-привязки и сохраняет последнего активного administrator.
Имя OTP-созданного customer может отсутствовать: это явный `null`, не
сгенерированное имя.
