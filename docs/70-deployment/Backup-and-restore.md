# Надёжность, резервное копирование и восстановление

Перед применением миграций `deploy/deploy.sh` создаёт сжатый дамп PostgreSQL через `pg_dump` в `/srv/expressa/<среда>/backups/`. Это локальная защитная копия перед поставкой; скрипт прекращает поставку, если дамп пустой или команда завершается с ошибкой.

Состояния `state/current` и `state/previous` содержат три immutable digest-образа. При ошибке шага развёртывания обработчик завершения возвращает изменённые сервисы к текущему состоянию; оператор может также вызвать `deploy.sh --environment <среда> rollback all|backend|front|back`.

Предварительный backup, компонентный rollback и последующее восстановление утверждённого набора доказаны на живом development-стенде запусками из [[CI-CD]]. Ежедневный шифрованный backup, политика хранения, изолированный restore drill, согласованные RPO/RTO и мониторинг backup пока не реализованы; это работа E12, а не выполненное свойство E01.
