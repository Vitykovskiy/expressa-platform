# Протокол обновления

Этот протокол определяет, когда обновляется документация и какая краткая
трасса решения нужна до зависимого кода, текста или поставки.

До первого действия автор назначения фиксирует краткую трассу применимости по
[агентной системе](../80-conventions/Agent-system.md): источник нормы,
ожидаемое поведение и инварианты, владельца состояния, границу компонентов,
критерий и способ доказательства. Для поставки трасса ссылается на решение о
version/changelog/tag по [правилам выпуска](../70-deployment/Release-and-version-compatibility.md).
Это содержание обычных inputs и criteria назначения, а не новый обязательный
файл, стадия или реестр.

Исполнитель обновляет затронутые trace, assignment и evidence до следующего
действия при условиях, указанных в [маршруте применимости](../80-conventions/Agent-system.md).
Ссылка сама по себе не доказывает применение нормы.

Если существующий контракт достаточен, новая документационная страница не
нужна. Если меняется долгоживущий контракт, его согласованный текст появляется
до зависимого кода и синхронизируется с этой партией. Тест проверяет выбранный
критерий и достижение нужной ветки; он не является источником требования и
зелёный прогон не заменяет независимые review и browser evidence.

Затронутые ноты обновляются вместе с кодом в том же pull request.

Каждая задача обновляет только соответствующие атомарные ноты в том же pull
request. Точные связи с контурной документацией определяют её README и INDEX;
не создавайте локальный протокол, если его нет.

Примеры связи:

| Изменение                       | Документация задачи                                                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Новый endpoint                  | OpenAPI, нота в `50-http-api/` backend и, если клиент использует endpoint, затронутая нота в его `50-api-integration/` |
| Новая переменная окружения      | Нота окружения в `70-deployment/` и `.env.example`                                                                     |
| Новая миграция                  | Нота в `60-data-and-integrations/`; при изменении процедуры поставки — нота в `70-deployment/`                         |
| Новый UI-компонент              | Нота затронутого пользовательского сценария или UI-контракт, если меняется его долгоживущий контракт                   |
| Новый пользовательский сценарий | Нота в `40-features/` и затронутая нота в `95-testing/`                                                                |
| Новая эксплуатационная команда  | Корневой `README.md` и затронутая нота в `70-deployment/`                                                              |
| Новое архитектурное решение     | Новый ADR в `20-architecture/ADR/`                                                                                     |
