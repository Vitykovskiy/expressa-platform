# Как пользоваться базой знаний

### 2.3. Документация

Документация каждого репозитория организована как связанная база знаний в
`docs/`. Корневой `README.md` служит точкой входа: объясняет назначение
репозитория и ведёт к `docs/INDEX.md`.

База знаний строится по следующим правилам:

- одна нота описывает одну концепцию, поведение, контракт или архитектурное решение;
- `INDEX.md` служит локальной картой, а `_MOC-*.md` — сквозным тематическим маршрутом;
- каждая нота содержит метаданные `title`, `description`, `type`, `area`, `status`, `tags` и `updated`;
- внутренние и внешние ссылки оформляются относительными Markdown-ссылками с расширением файла;
- `docs/00-meta/` фиксирует правила использования базы знаний, именования нот, протокол обновления и словарь терминов;
- `docs/00-meta/Update-protocol.md` определяет, какие ноты обновляются при каждом типе изменения кода;
- затронутые ноты обновляются вместе с кодом в том же pull request.

## Поиск применимой документации

`AGENTS.md` определяет автоматически применимые ограничения и входы по области
ответственности;
он не является каталогом предметных случаев. `README.md` объясняет назначение
репозитория человеку и даёт крупные входы. Поиск знания начинается с
`INDEX.md`, а не с порядка файлов, глубины каталога или результата поиска.

| Роль источника     | Назначение                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| Нормативный        | Действующий контракт, DoD или процедура для точного вопроса в своей области.                                   |
| Факт реализации    | Код, схема, OpenAPI, конфигурация или наблюдение работающего приложения; подтверждает фактическое состояние.   |
| Решение            | Принятый ADR для архитектурного выбора.                                                                        |
| Операционный       | Каноническая инструкция для поддерживаемого действия.                                                          |
| Состояние процесса | `state.yaml` для разрешённого перехода; передача работы и отчёт дают доказательства, но не заменяют состояние. |
| Исторический       | Журнал, архив, бэклог и снимок источника; используются только для вопроса об истории.                          |

`INDEX.md` — обязательный локальный маршрутизатор задач и вопросов. Его строки
имеют три колонки: «Задача или вопрос», «Маршрут», «Роль результата». Строка
ведёт в более узкий `INDEX.md`, межконтурный `_MOC-*.md` или к терминальным
источникам. Она не повторяет процедуру или правило. `_MOC-*.md` соединяет
дополняющие источники для сквозного пути, но не меняет их приоритет.

Порядок поиска:

1. Опишите задачу: затронутые контуры, действие или этап работы, предмет либо
   точный идентификатор, среду и тип вопроса. Неизвестный признак
   оставьте неизвестным.
2. Примените инструкции пользователя и иерархию `AGENTS.md` от корневого
   каталога до
   рабочего каталога. Это выбирает ограничения, а не предметную документацию.
3. Для межконтурной задачи откройте `docs/INDEX.md`; для ограниченной контуром
   — `docs/INDEX.md` каждого затронутого контура. При нескольких контурах
   объедините маршруты, а не выбирайте первый.
4. Выберите строку по задаче или вопросу и последовательно переходите в более
   узкие `INDEX.md`. `_MOC-*.md` используйте только для действительно
   межконтурного или межпредметного пути.
5. Для точного экрана, сервиса, маршрута API, объекта схемы или объекта
   реализации проверьте применимый `COVERAGE.md` и закреплённую за ним ноту.
6. В терминальных источниках определите нужные роли и примените
   [приоритет источников](Source-precedence.md) к точному вопросу. Если нужны
   требуемое и фактическое поведение, прочтите оба источника.
7. Если маршрута нет, ищите последовательно: точный идентификатор в
   `COVERAGE.md` и документации затронутого контура; затем поля метаданных
   `title`, `description`, `tags`, `area`, `status`; затем заголовки, имена
   файлов и полный текст с обычными синонимами.
   Результат поиска — только кандидат: подтвердите ответственного, область,
   статус и роль
   через `INDEX.md`.

При равных текущих утверждениях одной роли и области зафиксируйте конфликт и не
меняйте зависимое поведение, пока ответственный не разрешит его. Не выбирайте источник
по близости ссылки, глубине каталога, порядку результата или давности. В
существующей трассе применимости и обновления фиксируйте описание задачи,
путь `INDEX.md`/`_MOC-*.md`, нормативный или операционный источник, факт
реализации и источник состояния процесса, когда он применим. Пересчитывайте
маршрут при смене задачи, области, этапа, среды, статуса или требования пользователя.

При добавлении, переименовании, перемещении или замене ноты её ответственный обновляет
строку родительского `INDEX.md`, роли терминальной ссылки и применимый
`COVERAGE.md`. Новая нота не получает приоритет только из-за ссылки или
места в каталоге. Игнорируемый файл с секретами может быть источником значений
для разрешённого потребителя, но не является документацией, источником
полномочий или предметом поиска; значения никогда не попадают в ноты, чат,
отчёты, команды, журналы или снимки экрана.

Метаданные сохраняют ответственность: `owner` отвечает за актуальность ноты и
её маршрута, `last_verified` фиксирует последнюю проверку, а `sources` ведут к
первоисточникам. Они помогают выбрать и проверить источник,
но не меняют его роль или приоритет.

Общий каркас для трёх репозиториев:

| Путь                    | Назначение                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `docs/README.md`        | Назначение базы знаний и ссылка на главную карту                                          |
| `docs/INDEX.md`         | Главная карта документации                                                                |
| `docs/00-meta/`         | Правила использования, именования и обновления, словарь                                   |
| `docs/10-overview/`     | Обзор проекта, запуск и стек                                                              |
| `docs/20-architecture/` | Архитектура и `ADR/` с записями архитектурных решений                                     |
| `docs/70-deployment/`   | Окружения, сборка, поставка и восстановление                                              |
| `docs/80-conventions/`  | Инженерные соглашения                                                                     |
| `docs/95-testing/`      | Стек, уровни, паттерны и покрытие тестами                                                 |
| `docs/_journal/`        | Краткие записи о существенных изменениях                                                  |
| `docs/_sources/`        | Зафиксированные исходные контракты и другие внешние источники, если они нужны репозиторию |

Предметные разделы адаптируются к ответственности репозитория:

| Репозиторий                   | Разделы                                                                                                                                                                                                                                               |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `front-office`, `back-office` | `30-core-layer/` — инфраструктура клиента; `40-features/` — пользовательские области; `50-api-integration/` — использование backend API и зафиксированного снимка OpenAPI из `docs/_sources/`; `60-ui-kit/` — компоненты, токены, темы и адаптивность |
| `backend`                     | `30-platform/` — общая серверная инфраструктура; `40-domain-modules/` — бизнес-модули; `50-http-api/` — публичный HTTP API; `60-data-and-integrations/` — хранение данных и внешние интеграции                                                        |
