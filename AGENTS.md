# AGENTS.md для Codex

Правила работы агентов в этом репозитории.
СФОРМУЛИРОВАННЫЕ НИЖЕ ПРИНЦИПЫ ДОЛЖНЫ ПРИМЕНЯТЬСЯ ВСЕГДА, КРОМЕ СЛУЧАЕВ, КОГДА ПОЛЬЗОВАТЕЛЬ ПРЯМО ПРОСИТ ОБ ОБРАТНОМ

## Обязательные пакты

- КРИТИЧНО: Codex обязан соблюдать global skill `codex-communication-pact` во всех ответах пользователю.
- КРИТИЧНО: Codex использует режим `caveman:caveman` как стиль сжатой коммуникации во всех ответах и рабочих сообщениях. Режим действует до явной просьбы пользователя отключить его и не отменяет требования global skill `codex-communication-pact`.
- КРИТИЧНО: Codex обязан соблюдать global skill `codex-orchestration-pact` при выполнении комплексных задач.
- КРИТИЧНО: Для комплексных задач Codex использует `caveman:cavecrew` для разведки, точечных правок и ревью через подагентов, когда это соответствует границам пакта оркестрации.
- КРИТИЧНО: Codex обязан соблюдать global skill `codex-documentation-pact` при создании, правке и ревью документации.
- КРИТИЧНО: Codex обязан соблюдать global skill `codex-ui-analysis-pact` при анализе и документировании UI-поведения экранов, компонентов и элементов.
- КРИТИЧНО: Codex обязан соблюдать global skill `codex-development-pact` при создании, правке и ревью кода.
- Перед правкой документации Codex читает актуальную версию global skill `codex-documentation-pact`.

- Нарушение любого пакта считается ошибкой выполнения задачи; при замечании пользователя Codex исправляет результат по соответствующему порядку исправления.

## Приоритеты принципов

- При конфликте правил применяйте приоритеты в таком порядке: корректность, безопасность, проверяемость, сопровождаемость, простота, скорость и лаконичность.
- Краткость не должна скрывать существенный риск, ошибку в предпосылках, архитектурное ограничение или причину выбранного решения.
- Простота не должна нарушать инварианты, обратную совместимость, тестируемость, границы ответственности и требования эксплуатации.

## KISS

- КРИТИЧНО: Вся разработка обязана соблюдать принцип KISS. Исключайте любую необоснованную сложность. При выборе решения простота и упрощение имеют приоритет над дополнительной функциональностью; выбирайте самое простое корректное решение, покрывающее текущие подтверждённые требования.
- Не добавляйте усложнения, новые абстракции, процессы, скрипты или сценарии «на будущее» без доказанной необходимости и явного согласования пользователя.
- Reviewer отклоняет необоснованное усложнение и требует упрощения.

## Границы автономности

Требует явного подтверждения пользователя:

- `git commit`, `git push`, force-push, tag, создание PR;
- major-upgrade
- крупные архитектурные изменения;
- удаление публичного API, используемой feature, `core`-сервиса или endpoint из `ApiEndpoint`.

Commit не считается новой задачей разработки; проверки, уже подтверждённые для того же diff, повторно не запускаются.
