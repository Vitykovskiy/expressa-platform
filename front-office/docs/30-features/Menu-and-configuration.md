# Меню и конфигурация

Маршрут `/` загружает публичное меню, показывает категории, товар и его
конфигурацию, затем добавляет готовую позицию в корзину. [Источники: page](../../src/pages/MenuPage.vue), [flow](../../src/features/menu/MenuFlow.vue).

Физическая `displayLabel` выводится на карточке и в конфигурации вместо
технического размера; для старого API остаётся отображение `S`/`M`/`L`.
Публичное меню не кэшируется, поэтому новая загрузка страницы после deployment
получает актуальный каталог.

На mobile Account находится в header на menu root, category и product, а не в
содержимом menu root. Он имеет ту же позицию для гостя и вошедшего customer;
оба входа открывают один диалог. Правила уведомлений определяет
[системная feature-нота](../../../docs/40-features/Track-history-and-repeat-order.md).

Видимые заголовки групп конфигурации не выводятся: соседние группы разделены
отступами, а варианты одной группы остаются в одной строке, пока хватает ширины.
Нулевая доплата рядом с названием модификатора не показывается, положительная
выводится как `N ₽`; цена варианта размера остаётся полной. `aria-live`,
`aria-pressed`, доступные имена fieldset, именованные кнопки плюс/минус делают
изменение конфигурации доступным с клавиатуры и для скринридера. Сетка расширяется
на 768/1024/1280px; длинные названия остаются в layout компонента.
[Источник: ProductDetailScreen](../../src/features/menu/ProductDetailScreen.vue),
[источник: MenuRootScreen](../../src/features/menu/MenuRootScreen.vue).

Данные приходят из `/public/menu`; `menu` store владеет loading/error, `cart`
store — добавлением и объединением конфигураций. [Источники: API](../../src/shared/api/public-menu.api.ts), [menu store](../../src/entities/customer/model/menu.store.ts), [cart store](../../src/entities/customer/model/cart.store.ts).

Состояния загрузки, ошибки и пустого меню образуют компактную композицию страницы:
заголовок, пояснение и индикатор, а для ошибки — человеческое объяснение и
одна кнопка «Повторить». Пустое меню не обещает сроков появления позиций.

Проверки: [MenuPage spec](../../src/pages/MenuPage.spec.ts), [MenuFlow spec](../../src/features/menu/MenuFlow.spec.ts), [configuration spec](../../src/features/menu/product-configuration.spec.ts).

Карта раздела: [сценарии](INDEX.md).

## Одна и несколько цен: принятый target UX

Текущий конфигуратор показывает физический `displayLabel`, но выбирает один из
фиксированных `S/M/L` и по умолчанию использует M. Целевой UX из
[ADR-006](../../../docs/20-architecture/ADR/ADR-006-product-variant-portions.md)
ещё не реализован.

После перехода на `/api/v3` товар с одной ценой показывает цену и, при наличии,
авторскую `portionLabel` как статический текст. Selector, placeholder и
искусственный choice отсутствуют, в том числе для штучного товара без подписи.

Товар с двумя и более ценами показывает пары точной подписи и цены в серверном
порядке. На экране товара используется одна нативная radio group с legend
`Порция`; её accessible name для каждого choice включает подпись, цену и
недоступность. Первый доступный choice выбран изначально. Недоступные choices
остаются видимыми, disabled и отмечены `Нет в наличии`; при нуле доступных
товар sold out, selector не пустует и добавление запрещено. Длинные подписи
переносятся без скрытия различающей части.

`modifierGroups` v3 сохраняются при разборе меню и выводятся существующими
fieldset-элементами конфигуратора. Обязательный бесплатный default уже выбран:
«Какао» показывает «Сладость» с «Сладкий», а чай и кофе — «Сахар» с «С
сахаром». Выбор участвует в сумме, позиции корзины и payload заказа; для
холодных готовых напитков и еды этих групп нет.

Модификаторы и количество остаются отдельными элементами конфигурации. Цена
берётся только из выбранной формы, без преобразования подписи в `S/M/L`, amount
или unit. Это target UX; component-проверки ещё не реализованы.
